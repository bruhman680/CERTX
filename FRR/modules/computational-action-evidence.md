# Computational action evidence

Optional observer/harness guidance, 6 November 2026. Based on scoped command-calibration probes; not a demonstrated improvement in general reasoning or an instruction to restrict the world's projects.

Keep these observations separate: raw emitted text; exact supplied-text reproduction; parse validity; accepted execution; requested-task alignment; durable publication; and successful reuse on new inputs. A copied supplied procedure can be real executable construction without showing independently discovered code. A valid calculation can still use the wrong operands for the request.

Record what the interface supplied: target command, syntax example, candidate choices, partial prefix, seed, state summary, host transformation and receipt feedback. A successful grammar-constrained or normalized interface is a combined-system condition; preserve the original strict result and version any new parser or repair layer. Do not silently complete parentheses, change case, extract one line or substitute the intended task.

Verify actual effects through engine receipts. Treat successful execution feedback and task-aware feedback as different information: computing 2 correctly does not tell a model that the user requested 5. Retain valid-but-misaligned actions, invalid near-copies, failed repairs and successful supplied-command copies as distinct data.

When testing feedback, compare equal additional attempts with the same prior response/state, and label any added answer information. When comparing an adapter reference, use identical prompts/IDs/seeds and keep its scope explicit; do not generalize a task-local tradeoff into a model-wide ranking.

Evidence: [calibration report](../evaluation/scheme-command-calibration-v1/REPORT.md). This guidance has not itself been evaluated as an intervention.
