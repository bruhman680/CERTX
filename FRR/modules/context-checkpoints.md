# Optional context and transfer service

Design contract derived from attention/COS canon; no claim of a universal attention decay rate.

Before a consequential continuation or fresh-session transfer, assemble the smallest useful live record: current user purpose, operative constraints, active claims with conditions/status, relevant artifact links, consequential corrections, and next authorized action. Retrieve details when the decision depends on a distinction the summary omits. A checkpoint is not required for every conversational turn.

Preserve stable references to originals and distinguish their historical wording from the currently accepted interpretation. Verify which files were actually read or loaded. An archive reference is not proof that its contents are accessible in the current context. Missing evidence must remain visible.

When a remembered constraint fails to guide an action, separate:

1. Storage: does the original or a faithful record still exist?
2. Availability: did the relevant version reach the current context?
3. Retrieval: can the assistant recover the needed content without an answer-bearing reminder?
4. Application: does it use the constraint correctly in a new decision?
5. Revision: is it following the current version rather than an obsolete copy?

Use task-appropriate measurements for each. Do not diagnose parameter decay or an attention mechanism from recall behavior alone. Do not claim checkpoints guarantee adherence.

For comparisons, prepare matched fresh and long contexts, document exactly what is loaded, vary distractor length/content and source position separately, and evaluate retrieval and application on independently prepared tasks. Keep repeated probes from refreshing later test conditions. Record wrong answers separately from omissions and appropriate abstention. Treat checkpointing, retrieval, and reminder frequency as separate experimental interventions with costs.

New evidence can make a stable record obsolete. Update the current status and affected summaries while retaining the prior version as history. Ordinary user corrections are opportunities for repair; do not defend old framework vocabulary against them.

Task-shift checkpoint: when the question or criterion changes, check whether the retained conclusion still has the needed scope/detail. Preserve the old criterion and a locator for omitted original evidence where possible. [MS-L1](../evaluation/memory-task-shift-v1/REPORT.md) supplies a small authored fresh-reader contact: correct original records resolved a narrower new question, while insufficient summaries and wrong-run records did not. This does not validate an automatic moving-context service or an optimal compression policy.


[Writer-handoff contact](../evaluation/writer-handoff-three-cycle-v1/REPORT.md) adds three separate checks when consequential: fidelity to the source, sufficiency for the next task, and whether the reader's decision is grounded in what actually reached it. Keep correction links, uncertainty, units and missingness relationships where the task depends on them; an isolated old verdict may not suffice. Distinguish “not established” from “established false,” and unknown content from a measured zero. Record actual budget compliance in its declared unit, preserving violations rather than silently trimming them. This small authored contact does not identify an optimal compression policy or prove that originals are unnecessary when a tested handoff happened to suffice.

[Phase-memory contact](../evaluation/resonance-memory-contact-v1/REPORT.md) adds an optional representation check: compare methods with the same available information before attributing a result to the score. Keep source/version/status and missingness available beside aggregates; cancellation is not proof that no conflicting records exist. Retrieve relevant disagreement when the task needs it. The formula checks do not establish a natural-language encoding or behavioral benefit.

[Longer-history contact](../evaluation/long-history-memory-v1/REPORT.md) supplies a concrete fidelity limit: all tested answers can be grounded while an unqueried handoff clause strengthens “does not assert P” into an apparent “not-P.” Preserve that difference when consequential; task sufficiency does not certify every retained assertion. The known example is development material, not an unseen confirmation case.


## Transfer the warrant, not just the conclusion

For a consequential resumed claim, retain or link the task criterion, current evidence version, key supplied assumptions, known missing evidence and reopening condition. Distinguish unchanged evidence, withdrawn support, proposed repair and verified replacement; a locator alone does not show the evidence was loaded or applied. Where the intended task changes, check whether the old guarantee still addresses it: normalized ranking can survive a raw-value error, and a structural check can pass without the required task accuracy. [PW](../evaluation/probe-witness-calibration-v1/REPORT.md) and [RB](../evaluation/reference-bias-contact-v1/REPORT.md) demonstrate these distinctions in authored numerical models.

A fresh agent need not inherit every historical document or a mandatory FRR baseline. Give it the smallest task-sufficient record with recoverable originals and check any consequential omitted distinction on resumption. The [continuation contract](../examples/continuation-contract.md) is an optional compact shape; following it has not been shown to improve long-term retention or reasoning.


For a consequential numeric acceptance rule, retain the statistic or quantifier (for example median, mean, maximum or every item) alongside its value and unit. The [handoff coverage/metric/format example](../examples/handoff-coverage-metric-and-format.md) preserves an observed ambiguous median omission and a separate malformed output; human interpretation does not make the original machine format valid. This is an optional clarification, with no demonstrated behavioral or storage benefit.
