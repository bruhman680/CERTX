# Optional context and transfer service

Design contract derived from attention/COS canon; no claim of a universal attention decay rate.

Before a consequential continuation or fresh-session transfer, assemble the smallest useful live record: current user purpose, operative constraints, active claims with conditions/status, relevant artifact links, consequential corrections, and next authorized action. Retrieve details when the decision depends on a distinction the summary omits. A checkpoint is not required for every conversational turn.

Preserve stable references to originals and distinguish their historical wording from the currently accepted interpretation. Verify which files were actually read or loaded. An archive reference is not proof that its contents are accessible in the current context. Missing evidence must remain visible.

When a remembered constraint fails to guide an action, separate:

1. Storage: does the original or a faithful record still exist?
2. Availability: did the relevant version reach the current context?
3. Retrieval: can the assistant recover the needed content without an answer-bearing reminder?
4. Application: does it use the constraint correctly in a new decision?
5. Revision: is it following the current version rather than an obsolete copy?

Use task-appropriate measurements for each. Do not diagnose parameter decay or an attention mechanism from recall behavior alone. Do not claim checkpoints guarantee adherence.

For comparisons, prepare matched fresh and long contexts, document exactly what is loaded, vary distractor length/content and source position separately, and evaluate retrieval and application on independently prepared tasks. Keep repeated probes from refreshing later test conditions. Record wrong answers separately from omissions and appropriate abstention. Treat checkpointing, retrieval, and reminder frequency as separate experimental interventions with costs.

New evidence can make a stable record obsolete. Update the current status and affected summaries while retaining the prior version as history. Ordinary user corrections are opportunities for repair; do not defend old framework vocabulary against them.
