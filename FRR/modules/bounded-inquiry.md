# Optional bounded inquiry host contract

Derived from canon batch 2; compatible with runtime 0.2. This is a design contract, not an implemented scheduler, universal law, or obligatory reasoning sequence.

Keep four independently inspectable records:

- User purpose and constraints, with the assistant's provisional interpretation distinguished from explicit instruction.
- Candidate branches, their domain interpretations, artifacts, conditions, evidence, and dormant residues.
- Knowledge gaps that could change a claim, representation, construction, or decision.
- Resources consumed: live branches, candidate bytes, tool calls, elapsed time, and archive storage where measurable.

For active search, choose a gap and the kind of source contact that could change it. Record the question, accessible sources, expected discriminating information, retrieved provenance, and resulting revision. Knowledge intake need not occur in open play when no external claim is at stake. Search and integration can pause when additional material would not change the informational situation.

Treat factual support, logical validity where applicable, relevance to purpose, and generative value as distinct judgments. Use measured scores only when their construction and calibration are available. Preserve a branch's exploratory value without converting it into empirical support.

When running a population-based experiment, declare caps as operational settings, not cognitive constants. Include live count, new branches per step, total steps or calls, per-candidate size, and archive retention. Process a snapshot of the live set; queue new candidates for a later step. Check budgets before expensive work and before admitting offspring. Track rejected or deferred branches as appropriate; resource exclusion is not refutation.

When compressing archives, preserve links to consequential artifacts, failed assumptions, and reopening conditions. Account for archive growth and retrieval costs. Do not promise recoverability after deleting the only detailed record.

Repetition can indicate a useful recurring structure or an unproductive loop. A hash match alone does not decide which. Check whether observations, assumptions, consequences, or available actions changed before calling a pass redundant.

Evaluate the host on actual tasks against simple rivals: a single active branch, a fixed small beam, or task-driven search without state-score gating. Measure task quality, relevant distinction preservation, and cost separately. An orchestrator that enforces caps demonstrates bounded scheduling; it does not by itself establish improved reasoning or emergent cognition.
