# Optional host contract: recoverable boundaries and local reopening

Design candidate, 7 October 2026. Compatible with runtime 0.2; not a scheduler implementation, measured improvement, mandatory sequence, or proposed universal ontology. Use only where shared records, summaries, agent groups, or retained artifacts make a boundary consequential.

## Purpose

Allow an inquiry to expand, stabilize, compress, and reopen without losing the distinctions needed for its current work. A boundary can protect useful organization while also hiding disagreement or preserving a shared error. Its persistence is separate from its correctness.

The host is the application or coordination layer holding records, loading context, controlling access, and spending resources. Prompt instructions cannot by themselves guarantee durable storage, retrieval, rollback, or agent independence.

## Declare the boundary when it matters

Specify what is being bounded: an active branch, communication group, writable record, summary, model domain, permission scope, or resource budget. Keep these meanings separate when their consequences differ. Record whether the boundary was imposed by a controller, adopted by users, or inferred from observed interaction. An inferred boundary requires a defined observation; a group name or configured split is not evidence of emergence.

Record only the details needed to recover consequential choices:

- What passes through the boundary and what is withheld, summarized, deferred, or forbidden.
- The behavior intended to survive compression, its horizon, allowed transformations/interventions, and any declared tolerance.
- The source references and versions needed to restore an erased distinction.
- The current status and conditions of retained claims, including corrections and unresolved alternatives.
- The event that would warrant reopening, where a meaningful trigger is known.

Open play need not supply numerical tolerances or predefined triggers. Increase explicitness when a boundary carries a prediction, decision, or execution obligation. Resource exclusion is not refutation; lack of present attention is not deletion.

## Compression must remain recoverable where claimed

Before retiring detail from live context, preserve a sufficient original or artifact if later reopening is promised. A link is useful only if its target exists and can be accessed. Distinguish archival existence, current availability, successful retrieval, and correct application; use the companion [context service](context-checkpoints.md).

When a summary starts doing consequential work, ask which currently merged cases could differ under the next observation, action, composition, or longer horizon. Restore only the distinction needed for that consequence. A local failure may call for a refined summary, measured field variable, history-aware model, narrower scope, or revised intervention—not reopening the entire archive.

Record loss honestly when the only detailed source has been deleted or cannot be accessed. Do not infer missing history from a coherent reconstruction and present it as recovered provenance.

## Reopen locally with an explicit scope

When a genuine residual appears, choose an accessible region of the inquiry: one assumption, branch, record, communication link, representation, or control rule. State what change could distinguish the live alternatives. Useful movements include rereading an original, introducing a rival, widening communication, reversing a construction, replacing a summary, or running a reversible experiment.

For consequential mutation, preserve a version or snapshot sufficient for the rollback being offered. Track dependencies actually touched; account separately for storage, reconstruction, and recomputation costs. Restoring one object does not automatically restore a surrounding field changed by its earlier execution.

Compare the changed branch with relevant retained obligations. For example, reopening an explanation should not silently discard a user constraint or reinstate a corrected claim elsewhere. If isolated work is possible, use it to make the change inspectable. If isolation is unavailable, bound the experiment to the authorized task and record known affected artifacts.

“Annealing” may remain a generative metaphor. Random perturbation, model sampling temperature, wider search, cache deletion, and physical heating are different operations. Select an operation by its task consequence; do not infer a semantic temperature or beneficial reopening from its name.

## Preserve truth status across persistence

Retained material can be a current result, historical wording, contradicted candidate, dormant possibility, or useful instrument from a failed argument. Give corrected claims a current status while preserving their earlier wording as history when useful. Durable consensus, repeated retrieval, or inheritance across agents does not validate the content.

When multiple agents use a shared substrate, record important common inputs and construction rules. Role diversity and separate responses may broaden exploration, but shared prompts, sources, benchmarks, or labels prevent treating agreement as independent evidential convergence.

## Evidence and optional evaluation

Implementation can demonstrate recoverable records, selective context loading, or bounded execution. It cannot establish improved reasoning without a suitable comparison. Where evaluated, compare local reopening with no intervention, task-driven rereading, and broader reopening under declared resource budgets. Separate task progress, preserved distinctions, obsolete-claim reuse, collateral loss, recovery success, and cost. Freeze calibration choices before held-out evaluation where practical. No numerical trigger is supplied here because none has been calibrated for FRR.

## Placement and lineage

Keep storage formats, access checks, dependency tracking, budgets, and rollback mechanics in optional host modules. The runtime prompt needs at most the existing behavioral obligation to preserve recoverable lineage and restore distinctions when consequential; it need not carry a new boundary checklist or fixed agent-role hierarchy.

This contract develops [bounded inquiry](bounded-inquiry.md) and [context checkpoints](context-checkpoints.md), drawing on the saved [swarm boundary curiosity](../lineage/SWARM_BOUNDARY_CURIOSITY.md), [local reopening exploration](../lineage/GEMINI_LOCAL_ANNEALING_EXPLORATION.md), [source weave](../lineage/RESEARCH_MAP.md), and [compression scout](../lineage/SCOUT_COARSE_GRAINING.md). Those records distinguish constructed diagnostics, reported but unreproduced swarm claims, source-supported domain results, and exploratory relationships. None establishes FRR efficacy or a universal wake-to-law threshold. This module changes no core prompt, schema, or archived source.
