# Optional evidence-triggered specialization

Use when an observed difficulty suggests a targeted change to a tool, observation, record or procedure. This supplements the [bounded loop](bounded-experiment-loop.md) and [verification layer](verification-layer.md); it does not replace open exploration or require a form for every thought. Source contact and limits: [HI-C1](../evaluation/harness-interface-contact-v1/REPORT.md).

## Before changing the system

Keep an identifiable base revision. Name one observed limitation and the component expected to affect it. Distinguish missing information, inaccessible information, missing operations, and a poorly chosen procedure. Allow multiple explanations and unresolved attribution.

Reuse an existing trial record to capture: parent/candidate revisions; public hypothesis; applicability evidence; changed component; inherited assumptions; evaluator/data revision; budget; expected helpful and harmful cases; raw output paths; and decision. No hidden internal reasoning transcript is needed.

## Use and assessment

Choose the simplest applicable procedure. Retain the base when no specialization has a justified fit. A numeric confidence supplied by an agent is not a calibrated reliability estimate. If a base attempt is used to select a specialist, include that attempt and routing overhead in the total cost, and specify how any side effects are isolated or retained.

Check completion against external task evidence where feasible. Preserve source access for resolving summaries and tool observations. A common parent makes sharing convenient and can also transmit a defect; inherited checks deserve regression coverage when a consequential assumption changes. No inheritance syntax is required.

Compare candidates with the relevant base, including easy, difficult and mismatched cases. Repeat promising comparisons at a budget set before seeing confirmation outcomes. Keep untouched confirmation tasks separate from selection. Report partial progress, complete success, errors, uncertainty and cost separately. Decline promotion when gains are fragile, applicability is unclear or the evidence is insufficient.

## History

Working navigation may change. Preserve creation-time derivation and subsequent corrections as distinct historical events or Git revisions. Do not overwrite an old run or verdict to make it agree with the current interpretation. Branch names and editable parent pointers alone are not a sufficient derivation record; hashes also need recoverable underlying artifacts.

## Scope

This optional guidance is adopted as a saved aid. It has not been shown to improve agent reasoning, long-term habits or all-domain performance. No autonomous router, new permissions, scheduler, FRR core revision or universal threshold is introduced.
