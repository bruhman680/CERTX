# Optional practice: content, history and feedback have separate receipts

From [real artifact and source contact](../evaluation/real-artifact-provenance-v1/REPORT.md),1 November 2026, America/Chicago. Optional bounded practices, not a new core/default or universal exploration gate.

Pin source versions and the question being answered. A branch head can settle what bytes that branch stored at a cutoff; it does not settle scientific truth. Keep actual parent IDs, path/tree/blob bindings and original snapshots before inferring semantic patch/revision/derivation. Content hashes bind content; they do not authenticate authors or grant authority.

If time matters, distinguish when a claim was received from the interval it asserts applicability. Preserve the earlier query coordinates and receipts after late corrections. Do not infer effective validity from a document heading or commit timestamp without an explicit contract.

Keep model proposal, verified source receipt, source authority, rationale and weight change separate. An emitted UNKNOWN is not calibrated absence recognition; an unproduced note is not an explanation. A useful token-level feedback signal may exist without a complete corrected answer, so test that signal directly before deciding whether self-distillation is promising. Conversely, a correct source fed by code does not mean the model learned the controller.

Do not count copied witnesses as independent confirmations. Before withdrawing support for a derived answer, retain whether sources were alternatives or jointly required; the flat source set is insufficient in general. This dependency mechanism is a future test, not implemented here.

Treat cache editing as an operation with its own semantics. Removing a message's KV access does not establish a fresh forward pass in which it never existed; retained states may carry its influence. Preserve model/tokenizer/settings/source bindings and measure correction effects before epistemic forgetting claims.

Keep source claims, independent arithmetic checks, actual runs and report-depth reviews distinguishable. Correct analytical mistakes alongside preserved originals. A proposed future test uses standing user authorization within scope; these notes introduce no new permission flow.
