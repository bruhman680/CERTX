# PID-C1: controller mechanics and the reference problem

Prospective illustrative numerical contact. One scalar first-order plant, seven fixed controllers, four scenarios. Three deterministic scenarios have one run per controller; noisy sensor has30paired seeds per controller:231runs, not231independent experiments. No LLM participants, provider API, real sensor or physical experiment. No gain search, post-result retuning, statistical superiority claim or neural-reasoning transfer claim.

Plant: y_next=y+.1*(-y+u+disturbance),400steps. PID drives a saturated actuator using error=reference-measurement. P gain.8, I gain.4, D gain.2, where active. Derivative uses negative measured-output differences to avoid reference-step derivative kick. First derivative estimate zero. Integral contribution updates by Ki*error*dt. Filter memory.85 where active. Conditional integration clamping rejects an integral increment when it would push an already saturated output further in the error direction. Same gains shared across relevant controllers; sharing gains is not optimal tuning per controller.

Controllers: P, PI, PI with clamping, PID, PID with derivative filter, PID with clamping, PID with both. The ablations separate filtering and anti-windup, while PI supplies a serious simpler rival. Every controller receives the same reference, disturbance and paired sensor-noise stream for each scenario/seed. Equal steps/measurement opportunities do not make actuator effort, variation or realized saturation equal.

Predictions before execution: integral action should remove steady offset in the constant-load case; clamping should reduce saturation-release recovery delay; filtering should reduce high-frequency actuator movement; PI may attain small displayed error with approximately.4true-state error when feedback is biased. Failures of these predictions are retained without tuning. No prediction that full PID wins every metric or that PID controls semantic truth.
