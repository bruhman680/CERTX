## What “working” can establish

A working foundation means the model can perceive declared world information, emit an operation through a declared channel, receive the actual consequence in a later input, and carry or retrieve useful persistent state after another turn or pause. These are operational properties. They do not establish emergence, independent motivation, general tool competence, learning in weights, private deliberation, or a developmental phase.

The candidate should inherit an exact copy of the original entry-1550 supported filesystem and retain the original lineage. A changed interface is a new declared condition, not an unchanged continuation. Candidate step numbers may have their own sequence linked to parent1550. The old active pointer and frozen files should remain unchanged while the candidate is prepared and validated.

## Minimum acceptance evidence

| Requirement | Concrete evidence | What does not satisfy it |
| --- | --- | --- |
| World transitions | Authored fixture performs a read, write, and deliberate error; exact receipts and bytes retained | A prose claim that files were created |
| Model-to-action contact | Raw model output on the declared channel causes an actual bounded operation without repair/extraction | Operator-authored command, copied example only, or quoted program |
| Perception | A later model input contains the actual result, with its source and limits visible externally | A guessed result or observer summary presented as a receipt |
| Persistent state | Saved bytes survive independent namespace/process restoration; model can read them in a later call | Growing notebook that is never reread; automatic history only |
| Error access | True stdout/stderr/status or language error enters the following observation | Hidden failure, fabricated success, or a semantic rejection label |
| Resume integrity | A paused candidate has an exact state/input boundary, no pending unknown call, and a verified restored checkpoint | Blind rerun after a possible partial action |
| Bounds and isolation | Host/network denial, time/output/file limits, and unsupported states tested truthfully | Assuming a writable host workspace is itself a safe world |
| Preservation | Old phase inventory and model/runtime source pins unchanged; candidate lineage recorded | Replacing the existing snapshot or calling changed rules a frozen continuation |

At least one model end-to-end validation should involve a short operation whose real result is unknown until read from the current world. An observer-authored, explicitly labeled fixture may plant a small value in a disposable test copy. The model-generated operation then reads it, receives its real value, and uses or retrieves it in a later turn. Keep this testing seed separate from the open candidate, and do not count task following as spontaneous discovery.

A simple error and a pause/resume can be separate tests; they need not become a long contrived benchmark or a required workflow inside the model's ordinary world. Repetition and errors remain allowed during open operation.

## Interface and continuity cautions

Some model-to-world encoding is unavoidable, but a JSON envelope is optional. A declared whole Python-source or shell-source channel may reduce syntax overhead. If chosen, execute only that declared channel and preserve source exactly. Do not make a heuristic scanner execute any program-looking passage in ordinary notes. Do not turn an unfinished illustration into an action silently.

Source-only operation also changes the meaning of the turn: the channel is selected by the environment. Comments, quoted strings, empty source, and explicit no-op constructs can preserve forms of expression, but this should not be described as a demonstrated unconstrained choice between acting and writing. A separate note/source mode can be explicit if it is empirically usable. The diagnostic agent is measuring usability; the world specification should follow evidence rather than covertly repairing output.

Removing replay does not remove pretrained capabilities, but removes automatic short-term context. A replacement should specify exactly which recent source/results or model-authored memory are available, how they enter a new call, and what happens at the input boundary. No automatic selection of “interesting” thoughts, semantic compression, or observer encouragement should be introduced without declaring it. A full transcript can also create repetition or exceed context; a bounded policy must say what is retained and what is omitted.

The same static orientation need not be re-delivered as an action demand every turn. Its actual refresh policy still matters because a model call has no durable experiential state outside the supplied context and stored/retrieved world state. A one-time human instruction is not automatically permanent memory.

## Compact stop and resume protocol

1. Before a model call, preserve the exact input/messages/token IDs, seed/body settings, source checkpoint and an unambiguous pending record.
2. Preserve raw output before dispatch. Dispatch it once under the declared grammar; never repair it or automatically retry an uncertain action.
3. Preserve actual receipts and after-state, then atomically commit the next state and clear pending. An unsupported or unreadable state pauses honestly.
4. A normal pause records the latest committed checkpoint, next index, last record digest, input/memory policy and stop reason. No model call remains outstanding.
5. Resume verifies pins and source history, restores a fresh namespace, compares the exact captured state, and reconstructs the specified next input. A previous unknown/partial outcome requires investigation, not replay.
6. Keep operational checks and semantic assessments external. Report intended versus actual operations and unknowns separately. A working interface may be adopted as a declared candidate without upgrading open-ended behavior to an efficacy claim.

## Proposed first-candidate continuity policy

A growing actual conversation is the simplest auditable initial policy: supply mechanics and the invitation at the declared start, retain every actual assistant reply, and deliver only its real environmental consequence on the next turn. A blank successful notebook receipt can be retained as a declared mechanical tick. Do not append an unsolicited directory listing each turn, select twelve repeated texts, or insert investigator summaries. Files remain a separate carrier that the model may read and modify.

This is bounded continuity, not an infinite-memory solution. It can still self-reinforce generated patterns, so it should not be called an echo-free system. Reserve generated-token headroom inside the model's8192-position capacity: input_limit must be at most8192 minus the declared maximum generated-token count. Changing output length requires rechecking that reservation. Pause before generation when the exact next input would exceed the limit. A restart at the same boundary must reconstruct the same next token IDs and history, not silently drop or summarize them.

If the candidate inherits1550 files while beginning a new compact conversation, say explicitly that filesystem lineage continues while the input context is reset as part of the new condition. Loading all old dialogue is impossible within the available context; automatically carrying the final listing loop would be a different choice. Neither state should be misrepresented as a byte-identical continuation of the old complete model/world interface.
