Two explicit policies operate on visible source/layout/target alone. Strict holds when any target record lacks status. Supported permits an unambiguous complete target value with additional name-only target record and retains a warning. Neither assumes that a name-only record supplies a contrary value, and neither settles unknown temporal/revision semantics. Both hold on conflicting complete target values, invalid target status, unattributed status-only records, malformed/unsupported schema, absent source or absent target. A known non-target partial or conflicting non-target statuses do not override the target's complete value. This tests a literal asserted-facts contract, not external truth, trustworthiness or version precedence.

JSON duplicate keys, repeated line/bracket fields and unknown keys must not silently last-write-win. Consistent complete duplicate target records remain visible as multiple witnesses; they do not count as independent confirmations. Source absence, partial target, conflict, invalid status, unsupported format and wrong target are distinct receipts, not all relabeled UNKNOWN. No hidden case kind/expected answer is available to verification or prompting.

A perfect checker score is functional coverage in this designed domain, not independent proof of a universal verifier. No oracle result enters the model input or validator. The validator already reads status literals: selected-worker success is not evidence the model supplies an otherwise unavailable semantic computation or improves on a mechanical mapping.
