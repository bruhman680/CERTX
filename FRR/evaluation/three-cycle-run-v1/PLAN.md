# Three bounded autonomous cycles

User explicitly requested three cycles of experimentation, learning, review and synced recordkeeping before handing back for review. This file precedes new executions. It is a local bounded work plan, not a background scheduler or permission to run indefinitely. Prior broad account-budget authorization does not supply visibility into limits.

## Cycle1 — noisy calibration

Move SR-C1 from stipulated exact operators toward noisy synthetic witness measurements and sampled outcomes. Compare coordinate-diverse and confounded interventions at equal declared statistical budgets; distinguish known, estimated and absent calibration. Freeze the detailed protocol in cycle1 before running. Coordinator interprets results and chooses the next discriminating step. Finite simulation tests only the authored model and procedure.

## Cycle2 — challenge the measurement contract

An independent reviewer proposes a rival to Cycle1's assumptions. Select a bounded exact counterexample or sampled stress test after seeing Cycle1, document that adaptation, then freeze the Cycle2 protocol before its execution. Candidate faults include joint reset dependence, biased witnesses or shared observation loss. No result-dependent retuning of Cycle1 or silent replacement of a failed prediction.

## Cycle3 — review, repair and sync

Review protocols, saved raw outputs, assumptions, budget accounting and conclusions. Run meaningful independent reanalysis or artifact checks and preserve failures/corrections. Refine only guidance justified by the findings, keeping scope explicit. Distinguish using the harness from showing that it improves reasoning. End with a self-contained report of all three cycles and remaining uncertainty; no automatic fourth cycle.

## Bounds and shared responsibilities

Use at most three delegated agents plus coordinator for targeted implementation, a rival analysis and review. Keep experiments local and small, using existing numerical dependencies; no external training, model API calls, package installations or service deployment. No need to search further unless a consequential technical question cannot be resolved from existing sources/code. Preserve original reports and raw outputs. Record statistical draw budgets separately from compute/time and all actual failed attempts. No queue completion or core prompt/schema change follows merely from a toy result. Readable-code/history restructuring stays deferred.
