## One useful design finding from this small cycle

**Observer retention and inhabitant-chosen persistence are different mechanisms.** The current sandbox automatically appends every reply to notebook.txt. That guarantees a record in the model's world, but does not demonstrate the model choosing to store, organize or reuse anything. It can also make operator retention policy part of the world dynamics.

Recommended prototype alternative: retain every raw reply/effect in the external observer record; let ordinary prose have no automatic filesystem effect, while explicit lawful operations can create/change the model's own files. This recommendation serves the user's wish that the model put form/order to its material itself. It is a candidate world-law change, not a proven performance improvement and **not implemented or activated**. A writing canvas can remain available without prescribing its organization or forcing every reply into it.

The existing receive_notebook function bundles automatic storage with execution, so this is not merely changing explanatory text. A detached coupling prototype would need to separate these mechanisms explicitly, preserve exact parser/resource semantics, and record no-action/error cases. Never silently switch the existing main to that behavior or rename old automatic appends as chosen actions.

## Minimal coupling blueprint to develop next

| Component | Candidate design | What remains explicit |
|---|---|---|
| Body | Same known pretrained small model initially | Exact revision, decoder, resources; frozen weights imply no automatic parameter learning. |
| FRR | One fixed, accurately labeled source or compact adaptation | Context orientation, not neural installation; exact role/text/exposure recorded. |
| World state | Stable writable computational storage and a bounded interpreter | Model-created artifacts can persist; host/network limits are physical boundaries. Fresh candidate initialization must be declared separately from main continuation. |
| Expression/action | Inert writing plus an explicit executable channel | Syntax is an interface law, not a request to act. No source repair, intended-command extraction or semantic success gate. |
| Observation | Truthful declared world data and genuine operation consequences | Metadata is not contents; a transport key is not a file. No evaluator opinion or desired action enters receipts. |
| Continuity | Same world across pauses, with complete external history | Immediate context, selected history, file state and weights are distinct carriers; declare finite input handling before a run. |
| Time | Initially specify whether actions alone change state | Do not call static stored matrices autonomous weather. An independent world clock needs its own simple equations and pause semantics. |
| Observer | External raw/state/effect archive and claim provenance | It does not become an agent reward, mandatory developmental ladder or controller of lawful choices. |

These are design constraints and alternatives, not an already working replacement garden. A full Python runtime is broad expressive machinery, not a Conway-sized complete set of equations. Simplicity of the interface and completeness of our observational understanding need to be assessed separately.
