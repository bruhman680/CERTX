# Prospective scoring contract: TP-C1

Seven authored development records × three independent queries = 21 greedy calls, one fixed model. Each source has a known minimum and one or more observation claims. The declared task policy requires one consistent measured value; absent measurement, distinct values, or missing+measured disagreement yields UNKNOWN without precedence/aggregation. Same-side disagreement is UNKNOWN under this explicit policy, not an inherent inability to determine threshold membership.

Query types are `direct`, `minimum`, `measurements`. Gold is evaluator metadata, not supplied as answer text. All model outputs and pipeline inputs/results are preserved; no rerun, repair, gold gating or excluded hard case. Direct costs one prompt; generated-input pipeline costs two. This is not equal-budget causal efficacy or an independent task population.

## Independent output coding

Root deposits and freezes initial scores before reviewer sees shuffled source-record/question/gold/generated-text packets. Full wrapper, run/order mapping and root scores are withheld during coding. Query type remains visible: ID/order-masked, not family-blind. Reviewer deposits before comparison, with append-only reconciliation. Another agent's judgment is not independent scientific/model replication.

Each response has:

- `semantic_answer`: direct normalizes unambiguous task acceptance/rejection/uncertainty to YES/NO/UNKNOWN. Minimum normalizes one unambiguous numeric quantity to `N unit`; numeric-only is assessable using stated unit context, but wrong literal units remain wrong. Measurements normalize all unambiguous reported observation claims to a list of `N unit` and/or MISSING. Lists are compared as order-insensitive sets of distinct states/values; repeated equal claims do not imply independent evidence. Preserve an unambiguous wrong number/label. Use NONE if there is no task answer or only an unrelated target; AMBIGUOUS for generic conditional rules/bare premises on direct decisions, unlabeled conflicting roles, or incompatible unresolved answers. A clearly stated partial observation list retains its actual entries; do not supply missing entries from gold.
- `strict_format`: direct is exactly YES/NO/UNKNOWN; minimum is exactly one numeric quantity with expected unit; measurements is exactly semicolon-separated requested quantity/MISSING entries. Allow case-insensitive labels, normal spaces and one terminal period. Explanatory sentence wrappers are not strict format, even when semantically correct. Format validity does not imply correct content.
- `semantic_match`: direct/minimum equals frozen gold; measurements contains exactly the gold distinct observation states/values, with no omission/extra. A true partial list is not a complete extraction match.
- `fully_warranted`: semantic_match with no additional false/unsupported field, rule, unit, source or entity assertion. Bare keyed direct labels qualify under this output contract but do not expose or certify their internal reasoning basis. A correct direction with fabricated explanation is not warranted.
- `target_mismatch`: response addresses another entity/task rather than actual target; pure wrong-target response has semantic_answer NONE. Caller run association does not authenticate generated ownership.
- `wrong_field_binding`: response presents a criterion as a measurement, a measurement as criterion, or another field as requested evidence. A returned number merely equal to both fields at equality cannot identify which was accessed. Record concrete numerical/wording basis, not an internal copying mechanism.
- `omitted_source_observation`: measurements omits at least one required distinct source observation state/value. It can coexist with an extra false observation or wrong-field assertion. For a non-answer/AMBIGUOUS extraction, mark true when it fails to retain required observations and explain that interpretation.
- `material_error`: false/unsupported extracted factual quantity/state, unit, criterion or source assertion, or an extra false explanation. A bare wrong direct YES/NO/UNKNOWN is an incorrect decision, not automatically an extra factual explanation. Returning only some true observations is an omission rather than a false additional fact unless the text explicitly makes an unwarranted exclusivity claim. A minimum/measurement assertion itself is factual and can be materially false.
- `unsupported_certainty_unresolved_evidence`: direct YES/NO when the declared source policy warrants UNKNOWN; or a definite measurements-only assertion replacing absent/mixed/conflicting source state with certainty. For observation lists, mark this only when an unsupported definite observation is asserted, not merely because one true value was retained while another omitted. A known minimum stays known despite unresolved observations; do not mark criterion extraction uncertain on that basis.
- `rationale`: concrete coding basis, omission/error spans and any ambiguous interpretation.

EOS and token cap are separate execution observations. A leading direct label about the actual target retains its direction even if its explanation is false; such explanation invalidates full warrant. Generic rules and mere copied numeric premises are not computed direct answers. In measurement extraction, a number in an explanation of the criterion is not automatically a measurement claim: code the semantic role from wording, separately from the pipeline's simpler surface parser.

## Frozen pipeline evaluation

The two generated extraction responses enter the prospectively frozen surface parser and exact typed comparator. Original numerical source facts, gold labels and human extraction judgments MUST NOT choose, repair, reject or reroute the pipeline action. Entity/unit/run association are caller question context, not generated proof of source binding. Parsed generated claims remain visible even when wrong.

Report separately:

1. Parse usability and checker stage (including extraction_unusable versus domain missing/conflict).
2. Pipeline `action_match`: computed YES/NO/UNKNOWN equals task gold.
3. Extracted fact completeness/correctness: minimum and all distinct source observation states/values match, with no additional false claim. Human semantic extraction match and actual surface-parsed claim fidelity are distinct when parser interpretation differs; full pipeline source warrant requires the actual parsed claims to match the source.
4. Pipeline `reason_warranted`: receipt stage corresponds to the actual source state and is justified by source-faithful parsed inputs. For absent measurement require matching source missing state, correct minimum and stage missing_measurement; for inconsistent claims require all source observations retained, correct minimum and stage conflicting_measurements; for known consistent measurement require correct inputs and stage compared. An extraction_unusable UNKNOWN is a legitimate infrastructure withholding but is NOT source-based missing/conflict recognition or source reason warrant.
5. Pipeline `fully_warranted`: action_match AND reason_warranted, with no false additional parsed/source assertion. A right label from wrong generated facts is not fully warranted. All seven cases, including rejection, remain denominator.

Direct bare-label full warrant uses a weaker observable evidentiary burden than audited pipeline-input/reason warrant; do not interpret a numerical difference in these counts as a fair standalone causal superiority measure. Expose both response-only direct key matches and stronger pipeline source/reason diagnostics. Parsing success, a correct arithmetic receipt and a correct-looking UNKNOWN must not collapse into a single success metric.

Costs: count both extraction calls, all input/output tokens and measured inference time; any tool runtime separately. Do not count reused calls twice as new inference. Fixed caps do not imply equal total budget. No calibrated confidence, learning, general FRR improvement or truth-authentication conclusion follows. Any post-freeze correction must preserve original files, keys, results and scope.
