## Result

The adapter works for the tested cases: real actor cells commit in their original order, then one separate physical tick is attempted. Files and normal errors retain their actual consequences. Pausing does not advance the material. Recovery at three known interruption points does not replay actor actions or duplicate a committed tick. This is now a real execution-world integration, rather than only the previous pure-state simulation.

It is not a running model candidate, a learning result, or a promise of sufficient complexity for emergence. Sixteen named integration checks pass. The original 21 pure byte-mechanics checks remain a separate earlier result, not additional independent replications of this adapter.

## World law implemented

The existing supplied Python/shell runtime, exact executable fences, resource ceilings and arbitrary persistent files remain available. No synthetic write/append/delete vocabulary is imposed on the model. Ordinary prose remains external writing, without an automatic notebook or execution effect.

An ordinary root-level file `field.bin` is the material. For adjacent byte pairs (a_i,b_i), a changing-world tick applies the reversible local rule from the preceding study:

    (a_i,b_i) -> (b_i, a_i XOR b_(i-1) XOR b_(i+1))

Neighbors wrap periodically. An odd trailing byte stays unchanged. Empty files are valid. The static condition uses the identity update. Both conditions initially contain exactly the same62 bytes. This named file and initial material are declared experimental additions; they are not silently inserted into candidate38.

The tick acts only if field.bin is a regular file. Deletion stays deleted. A directory or symlink remains untouched; the tick never follows a symlink as its material. A hardlink to a regular file shares the update through the same inode, with the link relationship retained in snapshots. The implementation opens with O_NOFOLLOW and writes in place. The guest's ordinary file permissions still apply. Inability to open/write produces an actual execution receipt; there is no permission repair, replacement seed or analyst correction. Other files are unaffected except genuine hardlink aliases of the material.

Static tick access also uses the same read/write-open prerequisite, though it does not write new contents. Thus both conditions can have real access errors. The counter called ticks counts **attempted** physical ticks after completed replies, including known failed tick executions. It must not be interpreted as a count of successful material updates.

Only completed actor batches, including a declared cell-count boundary, qualify for a tick. An incomplete actor batch does not. An unfinished individual operation pauses with evidence; the adapter does not guess whether it executed.

## Records and recovery

`adapter.py` wraps the unchanged chosen-persistence coupling and inherited execution engine. The wrapper records actor batch and physical tick separately. Engine steps count all committed engine operations, including physical ticks. External counters separately track completed replies, attempted ticks and actor operations. Observer records, plans and operator recovery reasons are outside /world.

An outer pending marker prevents a new reply while a reply/tick outcome is unresolved. The existing underlying engine continues to guard individual process outcomes. Explicit recovery can finish a known completed actor batch by executing its not-yet-attempted tick, or seal the already committed tick and final counters. It never automatically reexecutes an actor cell. Identical completed reply retries return the saved record; conflicting identity reuse refuses.

No transaction can retroactively undo a real subprocess effect. If an individual process outcome is uncertain, recovery refuses and preserves evidence. The tests exercise interruptions after the actor batch, after the committed tick, and after final record/counters before pending-marker cleanup. They do not cover every instruction boundary, OS crash, power loss, disk fault, concurrent-writer race or capture failure. The single-owner underlying engine and declared dependencies remain prerequisites. Unknown runtime effects must not be converted into an apparently clean continuation.
