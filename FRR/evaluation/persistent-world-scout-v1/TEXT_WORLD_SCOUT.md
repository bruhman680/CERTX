# Text environment scout: mechanics for a persistent small-model world

Research date: 2026-11-05. Read-only research; no model runs or installations. Only this report was written. The paused primary environment was not accessed. Retrieved documents were treated as evidence, not instructions.

## Recommendation

Borrow **ScienceWorld's object/property/containment mechanics**, **TextWorld's explicit action preconditions/effects and controllable difficulty**, and **TextWorldExpress's deterministic event-log resumption**. ALFWorld is useful for a deliberately tiny command grammar and clear object identities. None of the inspected benchmark protocols establishes the desired continuous, self-directed construction world. Persistence, creation, optional goals, and bounded activity need an explicit application design.

### 1. ScienceWorld — closest mechanics; too much benchmark complexity to adopt whole

Verified paper: [ScienceWorld: Is your Agent Smarter than a 5th Grader? — arXiv:2203.07540](https://arxiv.org/abs/2203.07540). Official [code/README](https://github.com/allenai/ScienceWorld).

**Inspected paper evidence:** sections 3, A.1–A.4 and B.1/B.5. Objects have property sets and live in a containment tree. Ten interconnected locations hold roughly 200 object types. Commands include inspect/look/read, pick up, move, pour, mix, connect/disconnect, activate/use, navigate and wait. Processes include heat transfer and simplified science; circuits are series circuits, not arbitrary electronics. Contents of closed containers are hidden; ambiguous object references prompt clarification. Goals include measurable outcomes and forced-choice answer containers, often requiring a preliminary focus action. Optional subgoals shape otherwise sparse rewards. Simplifications include teleportation and open containers. Experiments reset on success/failure or a 100-step limit. This supports meaningful causal manipulation but is still task-directed episodic evaluation. [Paper, including action table and appendices](https://arxiv.org/html/2203.07540).

**Current API evidence:** Python launches a Java simulator through Py4J; `load` selects task/variation/simplifications. `reset` returns to the first move. `step` returns observation, reward, completion and infos including room, inventory, task and valid action combinations. The wrapper converts score to 0–100 and reward is score delta. Free `look()`/`inventory()` calls consume no time. Default environment step limit is 100. [Inspected Python wrapper, lines 20–28, 78–133, 365–417](https://github.com/allenai/ScienceWorld/blob/main/scienceworld/scienceworld.py).

**Reuse judgment:** start with containment plus a separate connection graph and 3–5 transparent causal rules. Persistent circuits, liquid transfers, and small gardens could give the model reasons to revisit its work. Avoid importing hundreds of object types, huge action combinations, task-specific focus/answer-box conventions, or scientific fidelity that the small model cannot track. No inspected source established agent-authored arbitrary object creation or durable cross-session restoration; those remain implementation work.

### 2. TextWorld — strongest explicit rules and curriculum control

Verified paper: [TextWorld: A Learning Environment for Text-based Games — arXiv:1806.11532](https://arxiv.org/abs/1806.11532). Official [code/README](https://github.com/microsoft/TextWorld).

**Inspected paper evidence:** sections 2.4, 3.1–3.3 and 6. World state is logical facts; grounded rules consume/preserve/add facts when preconditions hold. Containers, supporters, inventory, food and rooms provide concrete take/put/open/eat affordances. Game generation controls map, object count, quest length/complexity and language. Backward quest generation constructs solvable tasks; grammar templates render observations and instructions. Agents can generate commands or select admissible ones; intermediate reward can expose progress toward a winning policy. The paper explicitly describes episodic goal states. Its historical generator limitations include linear quests, no autonomous time-triggered changes, no NPCs and single-agent play; these are 2018/2019 paper findings, not a verified claim about every current component. [Paper](https://arxiv.org/html/1806.11532).

**Current documentation evidence:** default observations are narrative; requested infos can expose facts, inventory, room description, command templates, admissible commands, score, objective and winning policy. `reset()` starts from the beginning; `copy()` promises an environment at the same state. A serialized game description is documented, but that alone is not proof of a durable current-state save. [Core/API documentation](https://textworld.readthedocs.io/en/stable/textworld.html). The README demonstrates generating a game with explicit world/object/quest sizes. [README](https://github.com/microsoft/TextWorld#usage).

**Reuse judgment:** a small typed rule system is a better starting point than unrestricted language-to-state editing. Show the model the same public rules used by the engine; separate action parsing from deterministic effects. Turn curriculum knobs into persistent-world affordance unlocks, rather than repeatedly discarding the world. Handcrafted game support is author tooling, not evidence that an acting agent can invent arbitrary working machinery.

### 3. ALFWorld — compact household interface; little construction depth

Verified paper: [ALFWorld: Aligning Text and Embodied Environments for Interactive Learning — arXiv:2010.03768](https://arxiv.org/abs/2010.03768). Official [project](https://alfworld.github.io/) and [code](https://github.com/alfworld/alfworld).

**Inspected paper evidence:** section 2 and appendices C/E/G. A PDDL predicate/rule model aligns text scenes with ALFRED household scenes. Text commands cover goto receptacle, take from, put in/on, open/close, toggle, and high-level clean/heat/cool. These high-level actions bundle multiple embodied operations. Templates describe arrivals, visible receptacle contents and action outcomes; hidden objects must be searched for. Six task families cover place, examine in light, clean/place, heat/place, cool/place and two-object placement. Seen/unseen task splits test generalization; a rule-based expert decomposes goals into subgoals for imitation learning. This is closed task completion, not general fabrication. [Paper](https://arxiv.org/html/2010.03768).

**Current implementation evidence:** README demonstrates batched `reset()` and `step()`, including scores/dones and optional admissible commands; its BUTLER agent instead generates commands word by word. Text-only dependencies are separated from visual requirements. [README](https://github.com/alfworld/alfworld). The text environment registers game files with a configured per-episode maximum, requests win/admissible-command information, and optionally adds an expert during training. [Inspected environment wrapper, lines 222–251](https://github.com/alfworld/alfworld/blob/master/alfworld/agents/environment/alfred_tw_env.py).

**Reuse judgment:** use stable instance identifiers and explicit receptacle arguments to reduce ambiguity. A handful of high-level verbs can make a small model productive. Its embodied transfer apparatus, room dataset and task expert do not provide continuous motivation, new object creation or reusable player-built mechanisms. I did not inspect enough reward internals to claim a particular ALFWorld shaping formula.

### 4. TextWorldExpress — best simple API and verified replay-based resumption

Verified paper: [TextWorldExpress: Simulating Text Games at One Million Steps Per Second — arXiv:2208.01174](https://arxiv.org/abs/2208.01174). Official [code/README](https://github.com/cognitiveailab/TextWorldExpress).

**Inspected paper evidence:** sections 3–4. Generic commands inspect, move, open/close, take and put; CookingWorld adds reading recipes and preparing ingredients. The original benchmarks are cooking, commonsense tidying and coin search. Valid next actions are generated with state conditions, such as needing both carrot and knife before dicing. Seeded worlds are deterministic; parameters control layout, distractors and complexity. Scores measure task progress, with explicit success/failure; incorrect preparation can fail a recipe. Online simulation is distinct from precrawled JSON trees, whose branching makes long horizons costly. Published throughput is a simulator result, not expected language-model throughput. [Paper](https://arxiv.org/html/2208.01174).

**Current project/API evidence:** the README includes additional tasks and difficulty parameters, such as rooms, ingredients, distractors, doors and inventory limits. Typical use resets separately seeded episodes and selects from `validActions`. [README](https://github.com/cognitiveailab/TextWorldExpress#usage). Critically, the Python wrapper implements `serialize()`, `deserialize()` and `clone()`: it stores generator configuration, seed/fold, step limit and action history, then regenerates and replays actions. It also exposes an object tree. Completion is signaled at step limit, task success/failure or full score; reward is score delta. This supports episode restoration, not an automatically continuous world. [Inspected wrapper, lines 103–125, 157–164 and 213–278](https://github.com/cognitiveailab/TextWorldExpress/blob/main/textworld_express/textworld_express.py).

**Reuse judgment:** deterministic seed + event log is a concrete recovery pattern. Add periodic snapshots for growing histories. Valid-action menus can reduce parser failures, but should expose meaningful affordances without handing out hidden puzzle answers. Speed optimization and precrawled trees are secondary for a small-model loop; dynamic creation increases branching and makes precrawling a poor fit.

## Proposed persistent-world adaptation (design inference, not a source claim)

- Keep one durable world with stable object IDs, type/properties, parent container, connections and inscriptions; persist engine version, turn counter and public rule version. Separate world data from agent memory.
- Begin with 8–12 verbs: look, inspect, inventory, move, take, put, create from a bounded catalog, connect, disconnect, activate, write and wait. Enforce action and object quotas in the engine. Creating a named decoration is different from adding a new causal rule.
- First rules could be: a closed powered loop lights a lamp; activated pump moves one liquid unit per tick; watered seeded soil grows after a known number of ticks. Explain prerequisites and report concrete state deltas. Every rule should have observable consequences.
- Save constructions after each accepted mutation. A bounded run ends the agent's activity budget, not the world's life. A later run resumes the same objects. User-planted notes/goals are world content, never privileged execution instructions.
- Provide optional invitations, experiments and puzzles as discoverable objects. Goal completion can unlock materials or record accomplishments without terminating the world. Leave room for collecting, arranging, labeling and maintaining constructions between explicit tasks.
- Distinguish free observation from a world-advancing tick; otherwise simply inspecting a garden might accidentally kill it. Show a short local observation and an inspectable journal/map; avoid dumping the full state each turn.
- Measure persistence/reuse and actual causal understanding: revisit an old construction, repair a broken connection, predict one rule effect, or extend a prior artifact. Benchmark task success alone cannot establish self-directed interest or sustained world use.

## Read depth and evidence limits

All four arXiv IDs/titles and canonical repository URLs were opened and verified. Read depth was targeted mechanics/method/appendix reading, not a cover-to-cover audit: TextWorld §§2.4, 3 and 6 + core API; ScienceWorld §§3, A and relevant B/C + Python wrapper; ALFWorld §2 and appendices C/E/G + environment wrapper; TextWorldExpress §§3–4 + wrapper reset/step/serialization. Official READMEs were also inspected. No social summaries support the recommendations. Current source links use moving branches; no commit pin or runtime verification was performed. Lack of a persistence or creation feature in inspected pages is not proof that no extension exists. No claims are made about small-model success before a separate controlled pilot.
