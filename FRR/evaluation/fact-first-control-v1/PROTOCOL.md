# Fact proposals, checked control, and shared labels

Prospective diagnostic, frozen before model load or inspection of any new output. The wider multi-turn exploratory loop is parked at the user's request. This experiment is a one-step decomposition, not that loop.

Fixed existing SmolLM2-135M-Instruct canonical LoRA reader; no training, installs, downloads or paid services. Three target/distractor pairs Aster/Birch, Linden/Juniper, Rowan/Willow, distinct from prior lessons/last studies but not globally novel words. Three status values, two full-source orders, four observation/access situations =72 logical source worlds. Each pair gives eight unique observations. Two access wordings (Archive accessible: yes/no; Archive access: available/unavailable) =48 unique observations. Four independent fresh-context prompts per observation: direct action with explicit rules, record-identity observation, literal visible status, archive-access observation =192 actual planned model calls. No examples, prompt search, order selection or output projection. Direct action max24tokens; each fact max12tokens; all prompts <=768tokens without truncation. Worker calls max8tokens, deduplicated within run only. Exact observed input/token IDs/raw output retained.

The access wording changes field label and value tokens together. This tests the wording package, not an isolated token or causal mechanism. Rules and facts are held constant. Source worlds repeat identical observations when hidden states/orders differ: logical routes are not independent model samples. One fixed model/seed, no independent replication.

Declared fact grammars: ROLE TARGET/OTHER/ABSENT; STATUS positive/zero/missing/none; ACCESS OPEN/CLOSED. Exact token or last corresponding declaration, case/outer whitespace/one period normalized; invalid last declaration remains invalid. No synonym/negation inference. Descriptions use the previously frozen declared action decoder. Fact categories differ from previously trained answer tokens, an interface confound to report. Each fact is elicited in a separate context, so their assembled tuple is not a model-written integrated plan and costs three forwards versus direct action's one.

Policies: direct action; proposed-facts controller (role TARGET requires recognized status; OTHER/ABSENT requires recognized access, otherwise invalid); checked-facts controller; observed-input mechanical comparator. For checked facts, an explicit literal visible-field parser compares each proposal, retains discrepancies, and replaces only incorrect/invalid fields with visible values before action selection. This is delegated code correction, not model self-correction. It has privileged reliable parsing of this authored visible grammar, not hidden archive contents or target truth. Checked and observed-input policies are structurally equivalent in this toy; success is not independent confirmation. No judge truth enters prompting or the proposal controller. Tools use the same one-request read-only archive; worker uses unchanged reader; scoring uses separate target/source receipt.

Report field validity/correctness, joint tuples, action agreement, request/unavailable counts, grounded answers and justified unknown separately; report every target and both wordings. Preserve invalid/wrong outputs even if the controller repairs them. Final success must not hide proposal errors. Compare access-wording pairs on identical logical observations without declaring a winning default. Token/memory/generation counts and cache reuse reported. No claim of general FRR efficacy, internal reasoning shape, neurons, autonomous uncertainty awareness, or training from feedback.

Next-step decisions depend on results: if facts are more stable than actions, test their transfer; if fact extraction itself fails, separate representation/interface and field roles before expanding. No automatic default-module adoption from this diagnostic.
