## The implemented change

Earlier coupling appended every reply to notebook.txt before any complete code cells. That made observer retention into an automatic world operation. The new coupling records every raw reply externally, but ordinary prose has **no filesystem effect**. Only explicit complete Python/shell cells can modify the writable world. A model may choose to build files, programs or its own notebook; none is required or automatically created.

coupling.py invokes the pinned existing interpreter and exact fence parser while omitting the automatic note operation. This is an actual interface-law change, not a revised description over the old receive_notebook path. The old implementation and every historical world remain untouched. Source is not repaired, dedented or inferred from apparent intention. Up to eight complete cells execute literally in order. Ordinary errors remain visible and later cells remain allowed.

There are now three separate records of state: the supported world filesystem, the model's immediate conversation, and the external observer/effect archive. They have distinct persistence and limits. Fixed pretrained weights and fresh attention caches are explicit. A changing transcript is not a weight update; a stored observer record is not automatically a file available to the inhabitant.

These are real sandbox mechanics tests and logical fault injections, not model discoveries or independent replications. They cover specific transaction windows, not exhaustive OS failures or power-loss durability. The broad Python runtime remains more complex than a Conway-style complete mathematical specification. Supported filesystem capture is not every native OS detail or internal model state. Unsupported/unknown outcomes still pause with evidence retained.

World recovery verifies committed event/source ancestry against planned cells. It never automatically replays a cell. It may seal a known interrupted prefix with an explicit record of unexecuted remainder. An unknown individual operation, active owner or faulted state prevents that inference. The model-session layer separately retains its pending transaction if generation/effects are unresolved; world-prefix inspection does not silently repair session history.
