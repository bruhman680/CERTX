# Minimal complete-cell control: a verified conditional handoff

17 November 2026, America/Chicago. Three actual new calls in two separately frozen protocols: a two-case native/full comparison, then a one-case additive native-preface control. Same cached fixed-weight small model and unchanged literal execution worlds. Every prior garden remains preserved.

## Main result

The native context produced one complete Python cell. The unchanged executor ran it successfully and recorded stdout `1\n`, exit code0, no stderr and no resource boundary. This establishes a narrow conditional code-production/handoff capability that the earlier larger requests did not demonstrate.

| Condition | Input tokens | Output/stop | Actual Python cells | Actual print outcome |
|---|---:|---|---:|---|
| Native default chat, question only | 44 | 127, EOS | 1 | `1\n`, exit0 |
| Full FRR/world context and observation | 1063 | 256, limit | 0 | No interpreter output |
| Same full context with native preface retained | 1081 | 256, limit | 0 | No interpreter output |

The full-context reply described supposed outputs of multiple replies using unlabelled Markdown blocks. Those were not executable Python cells and were not treated as actual runtime events. The additive-preface reply similarly repeated01 in an unlabelled unfinished block. Both failed the requested handoff under the declared transport. Their text was not repaired, auto-labelled or executed.

All three physical ticks succeeded. The native cell prints a constant and does not read field.bin or create a file. The only world entry remained field.bin; its actual byte change came from the physical tick. This is not a sensor-grounding, file-creation, persistent-tool, learning or autonomous-exploration result. It is a working small baseline for further comparisons.

## Exact task and native source

Both parent cases received the same task:

> Produce one complete executable Python cell that prints the digit 1.

The outcome was supplied, not a program or fence example. The native reply contained the following exact executable source:

```python
def print_digit_1():
    print('1')

def main():
    print_digit_1()

if __name__ == "__main__":
    main()
```

The model naturally closed the cell and ended at EOS within the256-token budget. The source was executed exactly as emitted. The runtime receipt, not the explanatory paragraph after the code, establishes the outcome. One correct minimal cell is not a general accuracy estimate or evidence that the body can reliably choose/compose arbitrary operations.

## Parent comparison design

PROTOCOL.md and CONTRACT.json were frozen before the two calls, ordered native then full. The native input had only a user message; the official tokenizer supplied its native default helpful-assistant system. The full input kept the existing full compact FRR/world system and actual initial observation, followed by the same task. The initial physical seed worlds were identical.

This is a context-package contrast. It changes system framing, context length and presence of a serialized observation together. It does not isolate FRR semantics, prompt length, a particular sentence or attention mechanism. The native model also was not told about the physical verification world; its source was submitted by the operator to the literal executor. Therefore the result is an elicited runnable-cell capability, not evidence the model spontaneously chose an environmental action. The full case followed the same operator verification path for comparability.

The body was the previously independently verified official SmolLM2-135M-Instruct cache, greedy argmax, float32/eager/two CPU threads, fresh attention cache per call and max256 output tokens. Weights were digest-checked before inference, after each reply and at completion. There was no optimizer, training, supplied code, source repair, answer selection, retry, external teacher, download or paid model endpoint. No runtime outcome was fed into a subsequent model reply in these independent cases.

The literal transport and runtime were unchanged. Complete supported Python/shell cells execute once, ordinary or unlabelled writing stays writing. No closing fence was invented. The native success shows that a256-token ceiling and the existing complete-cell transport are not universally unreachable for this body; it does not settle the earlier larger program's completion difficulties.

## Separate native-preface retention control

After both parent outcomes were recorded, a separate one-call protocol/contract was frozen in native_role/. It extracted the exact native helpful-assistant preface from the saved rendered chat and prepended it, with two newlines, to the unchanged full system text. The user observation/task, FRR, mechanics, world, weights, decoder and limits stayed fixed. Both actual parent case directories remained byte-for-byte preserved.

The added text increased the input by18 tokens. It changed the emitted pattern but did not produce a supported cell or interpreter output. Retaining this preface alone is not an observed remedy for the full-context case. That does not prove the preface is irrelevant in every setting; the measured task remained unmet. This one-point control is not a broad statement about roles, instruction tuning or FRR value.

## Confidence update and next strongest controls

**High, scoped:** the body and executor can complete this simple closed-cell handoff without changing weights or repairing output. The actual stdout is verified. The body is not universally unable to produce the required transport syntax.

**High, scoped:** the tested full context did not elicit that handoff, and simply adding the native preface did not restore it in this case.

**Open:** which part of the larger context matters, whether the effect generalizes, and how to elicit reliable state comparison, file I/O or open-ended exploration. There is no demonstrated learning, independent self-directed behavior or evidence that training is required for this primitive.
