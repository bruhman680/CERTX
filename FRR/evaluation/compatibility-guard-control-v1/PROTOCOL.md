# Candidate compatibility control: frozen protocol

Written before running this experiment, 2 November 2026. CPU NumPy only; no inference or training. This directory contains a bounded source-pipeline extension, not an independent rebuild.

## Fixed design

Reuse the reviewed `open_world_guard.py` generator, original seven features, and original `care_claim_world`. Load only its definitions/imports/assignments before the phase-1 marker. Pin source and runner SHA-256 before execution in `INPUT_PINS.json`.

At each M in {100, 400, 1600}, use 800 independent fit runs and 800 calibration runs for each descriptive class IND, DIFF, SHARED (generated by COMMON). Fit per-feature means and standard deviations (floor .001). Calibration uses the empirical .99 quantile of mean squared standardized feature distance. These empirical bands have no claimed finite-sample coverage guarantee.

Candidate compatibility returns every class whose distance is at most its band threshold: no candidates -> UNKNOWN; multiple candidates -> UNRESOLVED; one candidate -> its descriptive name. No causal route is claimed. Compare against original F_care on the exact same 1,000 generated runs for each M/world. Store original F_care labels as well as their descriptive mapping (COMMON/COPY -> SHARED; UNRES_INDDIFF -> UNRESOLVED). Its supplied world-conditioned oracle probes remain a limitation even after descriptive mapping.

Worlds: IND, DIFF, COMMON, UPSTREAM, ANTI, LAG, DRIFT, PARTIAL, SWAP. COMMON and UPSTREAM have descriptive truth SHARED; the latter is not scored as an outside causal-route error. Other outside worlds have no supplied specific candidate truth. Distinguish wrong-specific claims, UNKNOWN, and UNRESOLVED. Report each world, never only an aggregate. SeedSequence root 202611021937; separate child seeds for fitting, calibration, evaluation, and care probes; separate world seeds. Save all parameters and per-evaluation features, distances, candidate masks and labels.

## Prospective predictions

1. The analytic DIFF noisy phi is 324/1771, below the original guard's .25 cutoff. Its conditional agreements are 853/2300, below the .6 override, so F_care's DIFF -> IND mistake tends to one as M grows. Predicted sampled DIFF wrong-specific rate is higher at M=1600 than M=100.
2. Candidate compatibility's known-DIFF wrong-specific rate at M=1600 is at most .05 and is lower than original F_care's. This is a falsifiable numerical prediction, not a guarantee from calibration.
3. At M=100 some evaluations have multiple compatible candidates; the set rule must expose these rather than pick a nearest label. No direction is predicted for total wrong-specific rate versus UNKNOWN: the control is not expected to solve all outside worlds.
4. Candidate compatibility UNKNOWN on SWAP is higher at M=1600 than M=400 because an existing OR-trend feature sees the change; no .80 target is asserted with these calibration seeds.
5. UPSTREAM and COMMON have the same passive generating law. Different sampled rates are sampling variation, not evidence of causal identification.

## Limits

All worlds, features and scoring categories are authored. Calibration is specific to M and flag-flip probability .05. No learned discovery, actual intervention, sham intervention, causal-source localization, general OOD guarantee, or model efficacy claim is tested. This is an engineering control for interpreting the earlier toy failures.
