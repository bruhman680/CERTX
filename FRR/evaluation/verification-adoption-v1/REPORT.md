## Amendment 02: loaded-source identity

Code review found a concrete attribution flaw in the prior checker: evaluate() reread the file hash when called, while an imported function could still execute older code. A /tmp reproduction imported source595fd389..., changed the file to reverse verdict logic, then observed the old supported verdict labeled by the new file hash. This can matter for long-running workers.

The repaired checker snapshots source identity on module import and refuses a substantive verdict if that file changes before evaluation. A fresh import after the change can evaluate under its new source identity. Non-object and nonfinite contracts now return unresolved instead of escaping the structured result path. This is a trusted-workspace binding improvement, not proof against source-read/import races, monkeypatching or a malicious runtime. It is not cryptographic authentication of executed bytecode.
