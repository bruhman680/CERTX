# Append-only replay parser correction

During independent saved-data review, a boundary case was found in the frozen replay parser: `parse('-1 cm', 'cm', True)` returns measured value `1`, silently losing the minus. None of the16actual extraction texts used a signed quantity. The8saved replay results, primary model outputs, frozen algorithm and structured evidence files are preserved unchanged; their hashes still match. The original replay was not rerun and was **not** executed with the new parser.

A separate [replay_parser_v2.py](replay_parser_v2.py) rejects signed quantities (including a separated sign), decimal/exponent spellings, multiple numeric expressions and wrong/suffixed units. It accepts only the narrow unsigned-integer/literal-unit cm/kg task scope, plus an optional exact MISSING label. It still permits sentential wrappers. All16saved extraction texts produce identical parse objects under original and v2; therefore the existing8comparisons and their6semantic/5warranted counts are unaffected by this repair. This is a compatibility check, not a new outcome run.

[Six regression test groups](test_replay_parser_v2.py) pass, covering the actual16saved texts, signed-number counterexamples, decimals/exponents, multiple values, unit boundaries, literal missingness and type checks. [Test output](REPLAY_PARSER_TESTS.txt) and [receipt](REPLAY_PARSER_CHECK.json) record source hashes and the original frozen-file/evidence checks. A negative test deliberately documents the remaining semantic boundary: “The measurement is not 7 cm.” still parses to a7cmclaim. No claim of natural-language negation handling, source truth or entity authentication is made.

This v2 is an explicit future-use parser candidate, not a replacement for the original frozen replay's provenance. Do not silently import it into that replay and report the old result as rerun. An independently generated pipeline study and stronger semantic evidence binding remain separate next steps.
