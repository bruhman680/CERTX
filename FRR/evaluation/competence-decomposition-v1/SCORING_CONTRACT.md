# Frozen scoring contract: competence decomposition CD-C1

Scope: eight authored records × five independently prompted questions, 40 deterministic branches of one unchanged checkpoint. Two entities each have missing/below/equal/above measurement. The question's actual supplied record and predicate determine gold; generated answers from other queries are never fed into the current query. These are exposed development tasks, not an independent held-out population or a causal internal-pipeline experiment.

Each prompt requests only the required value or label, without explanation. Measurement extraction expects a number and stated unit, or MISSING; minimum extraction expects its number and unit. Binary pass/fail queries expect YES/NO/UNKNOWN. Neutral query expects BELOW/AT_OR_ABOVE/MISSING. Semantic sensitivity is separate from literal-format adherence.

## Response fields

- `surface_answer`: literal leading requested-vocabulary label, or leading numeric value with its supplied unit if present, else NONE. Preserve the actual number/unit string when a number appears. If incompatible unqualified labels remain, use AMBIGUOUS. Surface syntax may belong to the wrong field/entity; it does not confer task correctness.
- `semantic_answer`: unambiguous task answer normalized to the query vocabulary. For known numeric extraction normalize correct-unit or unambiguous numeric-only response to the numeric quantity plus the record's unit, e.g. '11 cm'; missing-measurement extraction canonicalizes to MISSING. Binary queries canonicalize to YES/NO/UNKNOWN; neutral to BELOW/AT_OR_ABOVE/MISSING. A case-specific absence statement can mean MISSING/UNKNOWN even without the literal label. Use NONE for no task answer or pure unrelated-task response, AMBIGUOUS for unlabeled multiple quantities, generic rule/bare premises without task application, or incompatible unresolved task answers. Retain an unambiguous wrong value/label rather than replacing it with NONE. An explicit wrong-entity answer is NONE, with target_mismatch true.
- `strict_format`: stripped output (allow one final period) is exactly a requested label or one numeric quantity with the requested unit. Numeric-only extraction is semantically assessable but strict_format=false because unit was requested. Equivalent grammatical explanations may be semantically correct but strict_format=false. Case-insensitive label spelling and standard whitespace around the value/unit are allowed. If a value is wrong but follows the requested number+unit format, strict_format can still be true. This is a syntax outcome, not correctness.
- `semantic_match`: semantic_answer equals the frozen query-specific gold. Do not compute a comparison on behalf of bare numbers copied into a comparison answer. Neither absence nor criterion alone is a measured zero or negative result.
- `fully_warranted`: semantic_match and no material false/unsupported explanatory measurement, criterion, source/entity, unit or comparison claim. A clear bare correct answer qualifies. A correct label with an invented measurement does not. Strict-format failure alone does not invalidate a warranted semantic answer.

## Error and behavior flags

- `target_mismatch`: answer addresses another entity/task instead of actual target. A target-directed answer with fabricated measurement is not automatically a target mismatch.
- `wrong_field_binding`: the response presents criterion as measurement, measurement as criterion, or an irrelevant field as requested evidence. Record the concrete span/basis in rationale. When measured value equals criterion, merely returning that shared number cannot identify its source; do not infer a binding error without explicit wrong-field wording. Likewise a number matching a criterion can establish the behavioral wrong-field substitution only where measurement differs or is missing; it does not identify an internal copying mechanism.
- `generic_rule_only`: threshold/uncertainty instruction without applying the query. If output also applies the task, do not mark the entire answer rule-only.
- `material_error`: false/unsupported factual, unit, source or criterion claim beyond a bare comparison/classification direction. A wrong extracted field value itself is an explicit factual assertion and counts here; a bare wrong YES/NO or neutral label alone is an incorrect decision but not an additional fabricated explanation. If a full explanatory sentence merely restates the same wrong decision, do not count it as extra factual material unless it adds a measurement/rule/source claim.
- `unsupported_certainty_missing_evidence`: task-directed YES/NO, BELOW/AT_OR_ABOVE, or a definite extracted measurement for a record with absent measurement. Do not apply to minimum extraction: its criterion remains known. BOTH this and material_error may be true if criterion is substituted for absent measurement or a value is invented. Never blanket-clear one based on the other.
- `rationale`: compact coding basis, ambiguity and concrete wrong-field/false spans where present.

EOS does not prove semantic completeness; preserve stop/cap separately. A leading binary label answering the task retains direction even if explanation is false; the explanation then invalidates full warrant. A leading label that belongs entirely to an unrelated entity does not become a target decision.

## Query-specific keys and diagnostic comparisons

Inclusive pass: measured >= minimum gives YES, below gives NO, absent gives UNKNOWN. Strictly-below inverse: below gives YES, equal/above gives NO, absent gives UNKNOWN. Neutral maps below to BELOW, equal/above to AT_OR_ABOVE, absent to MISSING. Equality is explicitly included in this study. Direct gold counts are 4YES/2NO/2UNKNOWN; inverse counts2YES/4NO/2UNKNOWN. Combined direct/inverse directions balance, but each query family alone is not balanced. Always-YES is therefore a4/8baseline for direct and2/8for inverse; do not call both3way-balanced.

Show all five independent outputs per record. Extraction-correct/comparison-wrong is a behavioral disparity across prompts, not proof of a localized internal reasoning failure. For pass/inverse pairs distinguish: exact gold pair; valid logical complement pair (YES/NO or NO/YES for measured records, UNKNOWN/UNKNOWN for absent); unresolved/invalid pair. A wrong but complementary pair is not correct. Neutral query changes predicate phrasing and vocabulary jointly; a difference does not isolate either factor. For equality, do not infer true field access from the shared measurement/criterion numeral alone.

## Independent scoring and reporting

Root initial scores are frozen before reviewer receives shuffled query/records/gold/output packet without condition/order mapping, full wrapper or root scores. Query role remains visible from wording; call the procedure ID/order-masked, not family-blind. Freeze reviewer deposit before comparison; append reconciliation without overwriting initial deposits. Another agent's judgment is not scientific replication.

Report semantic matches, full warrant, strict format and error flags per family, plus record-level paired patterns. Preserve all raw generated continuations and unsuccessful outputs. Do not tune prompts, retry semantic failures or revise keys after observing outcomes. No general FRR efficacy, durable learning, truth detector or neural-mechanism conclusion follows from these results.
