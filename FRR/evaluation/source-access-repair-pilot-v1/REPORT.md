## What is ready, and the next useful distinction

The host now provides a tested route to read narrow experiment evidence and preserve a model's revisions without erasing earlier errors. This is useful infrastructure. It is not sufficient evidence that the small adapted model can choose and use that route, nor a general solution for all failures. External-world claims would need appropriate additional sources; these local records have bounded scope.

The strongest next calibration is tool-interface usability: a separate short-context command/request control, compared with the carried history, followed by an opportunity to interpret an actual returned record. That can distinguish a request-format bottleneck from context/serialization effects more cleanly than adding more tools. A later base-only versus canonical-adapter comparison could examine whether narrow prior adaptation matters. Keep all these as separately named conditions, not retrospective repairs of the original wandering trajectory.

The user's principle remains intact: preserve room for errors, exploration, revision and neutral outcomes. The empirical refinement is to distinguish **available access, successful invocation, exposure, use of evidence, and verified repair** rather than calling any one of them the others.
