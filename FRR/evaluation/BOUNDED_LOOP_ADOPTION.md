# Adoption of the optional bounded experiment loop

The user authorized adoption after the source review. The saved module is now an adopted optional execution procedure, discoverable from the package README, artifact harness, evaluation protocol, and current handoff. It is appropriate for bounded comparisons. Open play, conceptual wandering and inquiry into the objective itself remain available without a compulsory trial form.

## What changed

- [Bounded experiment loop](../modules/bounded-experiment-loop.md): candidate, evaluator and evidence-record separation; explicit decisions; noise and adaptive-selection limits; preservation before rollback.
- [Reusable trial card](../examples/bounded-trial-card.md): a concise set of fields, with existing protocols usable in place of another duplicate form.
- [Retrospective inquiry record](../examples/bounded-loop-retrospective.json): existing schema 0.1 records the earlier continuation pilot, its initial evaluator defect, repaired evaluation, and a prospective question that remains unrun.
- [Structural and evidence checks](../tools/check_bounded_loop.py): check that record against the existing schema, verify local references and archived evidence hashes, and check that the saved procedure is discoverable. The checker includes negative integrity controls.

The runtime prompt, compact prompt, and inquiry schema have not changed. This adopts an execution aid without making an unsupported claim of a better FRR reasoning version. No GPU training, provider API calls or fresh-agent effectiveness comparison was performed in this adoption step.

## Retrospective exercise, not a newly preregistered experiment

The existing [recovery pilot](RECOVERY_PILOT_REPORT.md) already has four conditions, a saved protocol, twelve outputs, initial and repaired scoring packets, and initial and repaired reviews. We mapped those records onto the trial procedure after observing the results. We did not invent advance predictions, a resource budget, or measured token/latency costs for that old experiment.

| Procedure obligation | Existing contact and remaining limit |
|---|---|
| Candidate and comparison | Ordinary/full-FRR guidance crossed with summary/original access; authored cases and unmatched guidance lengths limit attribution |
| Evaluator version | Both scoring packets and both reviews remain present; the correction note explains missing receipt details |
| Failed evidence survives | The original defective scoring construction and review are retained beside the repair; they are historical evidence, not the currently preferred assessment |
| Outcomes stay scoped | Central corrections survived all arms; detail omissions occurred in one summary-only chain; no general efficacy result follows |
| Resource accounting | Unknown costs remain unknown; no retrospective estimate is presented as a measurement |
| Future confirmation | A harder, independently prepared and cost-accounted continuation test remains pending |

This exercise checks whether our saved structures can represent a consequential failure and repair. It does not demonstrate a new agent following the procedure, an autonomous scheduler, tamper-proof storage, or improved research efficiency. The original pilot is a related retrospective case, not a trial conducted under today's newly adopted procedure.

## Verification and continuation

Run `python FRR/tools/check_package.py` and `python FRR/tools/check_bounded_loop.py` from the repository checkout; paths also work with the local lowercase `frr` directory. The second check verifies the record and seven original pilot-evidence hashes, unchanged core hashes, and local discovery links. In temporary data, negative controls require rejection of changed evidence bytes, missing evidence, and a path escaping the declared artifact root. These are integrity checks, not semantic judgments about the experiment.

The evidence manifest records paths relative to the FRR directory; it is a local integrity snapshot. It can detect a mismatch against its recorded hashes, but cannot authenticate itself or prevent a writer from changing both manifest and evidence. Git ancestry supplies an additional historical reference.

Executed checks passed: three inquiry records, seven preserved pilot artifacts, three unchanged core hashes, five discovery links, and all three negative integrity controls. The [saved receipt](results/bounded-loop-adoption-checks.json) contains the actual commands, exit codes and output. No existing behavioral case or historical experiment was rerun for this structural adoption.

For the next substantive bounded experiment, use the card before execution or link an existing complete protocol. Freeze development scoring separately from the candidate. Keep held-out confirmation unexposed, preserve unsuccessful trials, and save amendments before reusing a repaired evaluator. The current reset-preparation and continuation/retrieval questions remain open; this adoption does not silently mark either as executed.
