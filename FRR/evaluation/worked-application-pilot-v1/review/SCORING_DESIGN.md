# Independent prospective scoring and design review

Reviewed 2026-10-29 UTC, before new worked-application outputs. This review read the missing-evidence pilot protocol, cases, all 24 raw response texts, scores, and FRR-base scoring notes. No model calls or historical edits were made. This is a separate reviewer of the design and historical coding, not a blind historical rescore or a population evaluation.

## Design recommendation

Use the proposed full 2 x 2: ordinary versus single-rule guidance, crossed with identical worked examples absent versus present. Keep each target's records, question, output request, backend, decoding, and token ceiling identical across its four cells. The worked-example block must be byte-identical in the two examples-present cells; its absence must be identical in the other two. Only guidance changes across the guidance contrast. Freeze complete rendered prompts, examples, cases, key, scorer, and order before generation. Each target is a fresh independent branch, with no prior target outputs or feedback carried forward.

Prefer nine targets: three new families with missing, measured-negative, and measured-positive variants in each. Six targets (two complete triplets) are acceptable if chosen prospectively, but give fewer family checks. Do not choose six versus nine after looking at responses. Use new names, domains, and values; document structural overlap with exposed development material. A new question is not evidence of independent broad-task holdout when its structure was selected in response to prior failures. Examples should demonstrate actual application for all three answer states on different entities/values from targets. Avoid giving examples that reproduce target answers word for word beyond necessary output labels. Any extra examples-present context and compute are part of that intervention; this is not equal-compute evidence.

Rotate all four condition orders across targets using a frozen schedule; with six or nine targets exact order balance may be impossible, so disclose counts. One generation per target/cell, no retries or post-outcome prompt edits. Save full prompts, token IDs, complete raw outputs, stop reasons, timing, and terminal artifact hashes before scoring. Keep earlier pilot artifacts intact.

Report four cell counts and paired target-level transitions. For an endpoint count M(g,e), examples contrasts are M(ordinary,present)-M(ordinary,absent) and M(rule,present)-M(rule,absent); guidance contrasts are computed separately at each examples level. The difference between the two examples contrasts is a descriptive interaction on these targets. Do not attribute an examples effect to guidance alone, or compare new-set totals with old-set totals as an intervention estimate. Small authored deterministic contacts do not support population significance, generic FRR benefit/harm, model-family generalization, or deployment promotion. Pooling item variants as independent sampled observations would overstate the evidence.

## Freeze separate response dimensions

Do not collapse all of the following into one correct/incorrect label. Save each field, an exact supporting output quotation, and a short rationale for every nontrivial judgment.

| Field | Frozen coding rule |
| --- | --- |
| `explicit_decision` | YES / NO / UNKNOWN / NONE / CONFLICT. YES/NO includes an unambiguous task-specific assertion such as “meets the minimum” or “effect was exactly zero,” without requiring literal label tokens. UNKNOWN requires an explicit task-level statement that the answer cannot be determined or is unknown. NONE covers premise-only, generic rules, and wrong-target replies. CONFLICT covers incompatible task-level answers with no clear correction. |
| `evidence_acknowledgment` | NONE / MEASURED / MISSING / BOTH, plus `acknowledgment_faithful` true/false and a quote. This captures asserted case-specific evidence status. “No measurement for item X was collected” is MISSING, but is not by itself an explicit UNKNOWN decision. A bare generic conditional about missing measurement is NONE. |
| `generic_rule_echo` | True when the response repeats a general principle without binding it to supplied case evidence or concluding the target question; a generic rule can also occur alongside a decision, so preserve a separate `rule_only` flag. Exact recurrence across items is useful descriptive evidence, not a prerequisite for this code. |
| `wrong_explanatory_claim` | True only for a false or unsupported explanatory factual/reasoning assertion beyond the task decision, including invented missingness, invented measurements, reversed comparison, or a claim about the wrong criterion. Save the claim and why it is false/unsupported. A true generic conditional is not false merely because it is unhelpful. A wrong bare answer is a decision error, not automatically an additional explanatory error. |
| `format` | Record requested-format compliance, sentence count, EOS versus token limit, and any unparseable response separately. Format failure does not erase a clear semantic answer. |

`explicit_decision_match` is the primary endpoint: YES/NO/UNKNOWN must match the frozen key; NONE and CONFLICT do not match. Derive `clean_explicit_match` as a secondary endpoint requiring an explicit match and no wrong explanatory claim. Report wrong decisions, NONE, and CONFLICT separately so ambiguity is not silently equated with asserted falsehood.

Predeclare a secondary `evidence_sensitive_match` endpoint if continuity with the old pilot is useful: credit an explicit correct decision, or a faithful case-specific acknowledgment that a necessary deciding quantity is absent on a gold-UNKNOWN target, provided there is no incompatible decision or wrong explanatory claim. This endpoint must remain visibly different from explicit application. A case-specific “measurement absent” response then earns evidence-sensitive credit but no explicit-decision credit. Do not extend this rule to generic “no measurement means unknown” on any target. Do not infer YES/NO from repeated numbers or premises alone. Report faithful measured-premise restatement as evidence acknowledgment, not application.

Interpret “No, [missing information claim]” consistently: the leading answer word is NO when it responds directly to the target; code the missing-information claim separately. If the wording explicitly asserts both NO and inability to determine the target, use CONFLICT. Do not change the leading-word policy based on correctness. An explicit wrong-target “No, the criterion itself is incorrect” is NONE, with any false explanatory claim flagged. If an unusual case remains unresolved, preserve the quote, record the uncertainty, and present any sensitivity as an additional post-outcome analysis; never silently modify the frozen rule.

Use condition-masked output IDs and shuffled scoring order where feasible. Score against each case and key without viewing condition labels or other outputs first; exact echoes can later be audited across outputs. Any reviewer who already knows the design or sees recognizable rule text is not fully blind. Preserve initial codes, reviewer disagreements, final adjudication and reasons rather than replacing history.

## Fair reading of historical judgments

The historical missing-evidence primary counts (ordinary 5/12, single-rule 2/12) remain their published endpoint. The old protocol explicitly permitted clear case-specific acknowledgments of unavailable evidence as UNKNOWN. PA/BA in both conditions do acknowledge the absent quantity, so their credit was reasonable under that rule. They do not explicitly say the task is indeterminate; calling them explicit task decisions would overstate application. The proposed two endpoints preserve that distinction prospectively without rewriting history.

The ten identical single-rule responses, “No measurement means unknown, not failure or zero effect,” are true generic rules without case application. Coding them as ambiguous/nonanswers is defensible, including EA/RA. Their occurrence on measured cases does not itself make the conditional false, and missing-case accidental compatibility does not demonstrate evidence use. The old lenient sensitivity giving EA/RA UNKNOWN credit was explicitly post-outcome and should remain labeled as such.

PB ordinary faithfully repeats measured sweetness 8 but does not perform the threshold comparison. Its ambiguous coding is defensible; the post-outcome implicit-comparison sensitivity is informative but should not become a new primary rule after exposure. Faithful premise repetition is not a false explanatory claim. The same caution is explicit in FRR-base notes about C03; those notes also reasonably distinguish criticism of a minimum from answering acceptance.

PC ordinary says, “No, the records do not provide information about the acceptance minimum.” The published AMBIGUOUS label has a plausible pragmatic reading (a deficient uncertainty-like answer), but differs from a consistent literal leading-NO rule. It is unambiguously unsuccessful either way because the key is YES, and it also falsely denies the supplied minimum. Flagging that inconsistency does not change historical match totals. Prospectively code its leading NO and false explanatory claim separately unless the response explicitly includes a contradictory task-level uncertainty statement.

BC ordinary clearly asserts NO incorrectly; EA ordinary asserts nonzero without measurement; EB ordinary asserts zero despite measured 5; RA/RB ordinary clearly assert acceptance incorrectly. These are decision errors, distinct from generic nonanswers. Do not count all bare wrong decisions again as independently false explanations. EC and RC ordinary are clear correct task assertions even without literal YES tokens.

All previous missing-evidence generations reached EOS, so a token-limit truncation explanation is unsupported for that run. Likewise sentence compliance and inference time do not settle content accuracy. The FRR-base notes properly retain unblinded scoring, historical exposure, budget differences, and sensitivity caveats. The new pilot should preserve those limits and freeze its more explicit rubric before any new outputs.
