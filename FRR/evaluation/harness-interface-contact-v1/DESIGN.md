# Staged actual-agent comparison draft

Status: proposed, unexecuted, not preregistered. Adapt the existing source/exposure/repair bridge; do not treat this document as another queued family or as an instruction to launch every stage. The initial decision is whether better access helps grounded use of retained evidence while preserving relevant contradictions.

## Common preparation

Choose one existing evidence/handoff task family. Before any run, freeze task packets, task-specific expected evidence and explicit unresolved cases, assessor rubric/version, participant model and settings, per-attempt budget, replication count, exclusion rules and stopping rule. Use development material for instrument debugging and selection; reserve fresh confirmation items. Do not choose a sample size or promote a candidate after inspecting favorable outcomes. Keep FRR guidance identical across conditions so this does not confound interface effects with FRR effects.

Use fresh contexts and balanced/randomized condition assignment. Save prompts, available information, returned observations, actions, effective configurations and outcomes. Assessors should be blind to condition where feasible; disclose shared platform ancestry and any condition clues. Published benchmark results cannot supply our baseline rates or justify our sample size automatically.

## Stage A: information versus access

Start with a frozen complete record and an existing literal source-access tool. Compare raw text access against structured access over the same record. Structured output includes source IDs/revisions, field definitions and routes back to originals. Match the complete accessible task-relevant information and action permissions, not merely token counts. Measure actual exposures, calls and latency; different information reaching a bounded context can be part of the mechanism.

Include source records with accurate relevant data, accurate but mismatched runs, corrections/contradictions, and explicitly absent evidence. Introduce corrupted/donor records only as declared experimental manipulations. Distinguish an agent detecting a mismatch from following a cue that labels it wrong. Record unresolved decisions as appropriate when evidence is insufficient.

Task-specific outcomes: warranted conclusion, supporting-source match, treatment of contradictions, unjustified completion, appropriate uncertainty and measured resource cost. A higher rate of answers is not automatically improvement. Report all component outcomes rather than one opaque quality number.

A gain here supports scoped access/representation benefit under this reader/budget. It does not demonstrate new stored knowledge, physical memory, internal parameter learning or general FRR superiority. If a structured interface omits something consequential, preserve the failed design and revisit its information contract.

## Stage B: changed operations, only if consequential

Freeze the best-supported observation condition and record set. Compare existing primitive operations with a candidate helper implementing the same authorized transformation, both exposing inspectable results and equivalent final-state checks. Test failure paths as well as valid inputs. Report changed compute, privileges and bundled work. Tool capability effects cannot be inferred from Stage A alone.

## Stage C: routing, only after specialist performance is known

Freeze base and specialist candidates before evaluating routing. Compare base-only, specialist-always, and evidence-triggered choice; a task-only router can be a separate comparison if it answers a real question. Use mismatched/easy tasks as well as failure-bearing ones. Start each alternative from the same environment snapshot, or explicitly account for irreversible side effects; a base attempt must not covertly supply privileged state to only one condition.

Record exactly what the router saw and when, why a procedure applied, total base/router/specialist cost, errors introduced and base behavior preserved. Hold evaluator feedback out of routing. An oracle with hidden labels may provide a diagnostic ceiling only and must be labeled separately.

## Promotion and history

Promote only for the tested scope under a criterion fixed before confirmation, with uncertainty and adverse cases retained. If inconclusive, keep the base. Preserve original derivation, every attempted candidate, run output, selection decision and later reassessment; mutable navigation links should point to these rather than redefine them.

No stage was run in HI-C1. The independent soil reparameterization/leaky-reset contact remains a separate high-priority causal question; this design narrows the pending practical agent-memory bridge.
