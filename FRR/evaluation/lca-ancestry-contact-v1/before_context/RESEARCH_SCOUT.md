# Primary-source scout: tree LCA, DAG ancestry and Git merge bases

Fetch attempts and original failures are retained in sources/FETCH_LOG.json. Git's rendered documentation returned HTTP 403; two attempted academic PDF addresses returned HTTP 404. No content claims rely on those failed requests.

1. Git project's own manual source: https://raw.githubusercontent.com/git/git/master/Documentation/git-merge-base.adoc (fetched 200; saved as sources/git-merge-base.adoc). Lines 21–26 define a better common ancestor by ancestry rather than path depth, and explicitly allow several best common ancestors. Lines 122–135 illustrate criss-cross merges with two incomparable best ancestors; without --all the choice is unspecified. This directly supports returning all maximal common ancestors. Lines 32–45 distinguish default multi-argument hypothetical-merge semantics from --octopus, which computes ancestors common to all supplied commits. Our general nonempty query uses intersection over every queried node, not Git's default multi-argument operation. This tool does not invoke Git or claim Git commit authenticity.

2. NetworkX project's own implementation and documentation: https://raw.githubusercontent.com/networkx/networkx/main/networkx/algorithms/lowest_common_ancestors.py (fetched 200; saved as sources/networkx-lca.py). Lines 166–222 describe a separate tree routine, parent→child orientation and Tarjan's offline tree algorithm. Lines 242–255 reject multiple sources or in-degree greater than one for the tree case. Lines 101–120 include each queried node itself among its ancestors, intersect ancestor sets, then walk down to one terminal common ancestor. Despite the name all_pairs, this produces one ancestor per pair, not all incomparable LCAs for a pair. We therefore do not use that API as a set-valued correctness oracle.

A rooted tree has one path to the root per node; shared ancestors form a chain and its lowest member is unique. General DAGs admit multiple incomparable lowest ancestors, and disconnected roots may have no common ancestor. Longest/shortest path depths are not a substitute for the reachability partial order. Our two-LCA and shortcut tests exercise that distinction. Directions differ across conventions: NetworkX's tree documentation uses parent→child edges; our manifest explicitly stores child→parent edges so following parents enumerates ancestors.

Decision: implement a small optional bounded DAG query using explicit node IDs, direct parent declarations and optional byte bindings. Compute all maximal common ancestors under reflexive reachability. Reject invalid graphs, do not silently collapse several answers to one. Do not reinterpret flat registry shared hashes as a complete real ancestry graph. This contributes a provenance navigation primitive only; it supplies no truth, probability, causal independence, confidence or model evaluation conclusion.

The raw upstream URLs are mutable; exact downloaded bytes and their SHA256 are recorded in CHECKS.json. These are primary implementation/documentation sources, not a claim to have read the unavailable academic papers or an exhaustive literature review.
