# Index acquisition pilot: frozen design

Fresh fictional history: twelve records, two domains, three questions. One fresh reader per arm, two turns each. Both get the exact same handoff, questions, record IDs, dates and domains. Descriptive arm additionally gets a short manually authored content description for each record. This supplies extra information. It is not an equal-information reasoning or FRR efficacy comparison. No arm is FRR-branded. Root authors source/key/index and knows mapping; readers receive only their packet. Shared filesystem masking is instructional, not access isolation.

Two nonadaptive original-record lookups per reader. Save initial answers plus requests, deliver exactly requested records, save final answers. No hint, feedback, retries or cross-reader communication. Strict JSON validity scored separately from semantics; preserve malformed output. Count actual delivered records, initial/final full-source matches, conditional evidence warrant, decisive question rescue and appropriate unknowns. Missing target retrieval is not irrational by hidden-key hindsight. Descriptions may directly cue promising records; this is the intended information manipulation. No word-cap intervention, causal efficacy inference, statistical generalization or implicit cost equivalence.

Prior expectations: initial substantive answers should all be unresolved; Q1 requires corrected counts, Q2 must respect actual permission scope, Q3 remains unresolved. D04 serves Q1 and Q3; M04 directly serves Q2, while M02 also explicitly limits permission. A reader may discover useful support through a different valid record. Keep scoring open to actual evidence rather than privileging one ID. Do not treat finding an excluded subgroup as establishing its effect.

Preparation cost: root manually constructs twelve record descriptions using the full source. Report their added words/UTF-8 bytes and both full packet sizes. No claim of measured creation time, token billing or machine effort: those are unavailable. The basic arm uses no description construction beyond shared domain/date inventory. Only two fresh readers: outcomes are illustrative and confounded with reader variation.

Pre-execution review examines source/key, whether descriptions leak the outcome, packet parity outside inventory, and attribution limits. Freeze all scientific input bytes before reader dispatch; preserve review and corrections. A separate reviewer then checks raw outcomes and root scoring. Stop after this one pilot and review; no automatic follow-up or broad scout. Queue/core/schema and previous history unchanged. Next directions are proposed only.
