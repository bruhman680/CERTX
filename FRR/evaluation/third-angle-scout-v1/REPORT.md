## Five distinct ways capability can appear without a new weight update

### Random weights, constructed task-bearing soft prompt

[Hsu & Lai, Training-Free Universal Approximation by Prompting Random Transformers, 2608.09558v1](https://arxiv.org/html/2608.09558v1), August2026, is a closer **literal no-pretraining lead**, not a confirmed match. Root read setup, construction, random-weight rank conditions, numerical comparisons and future-work limits. A simplified single-layer random attention network can emulate kernel regression through specially constructed continuous prompts. Task information and computation enter the prompt construction; prompt length, norm and dimension have costs. This is neither an ordinary chat prompt nor a demonstration of untrained general language/world knowledge. The result makes external task-bearing representation a serious computational object without making knowledge appear from no source.

### Corpus counts in host memory, trained backbone retained

[Magnusson et al., The COUNT: Counting N-grams Unlocks Scaling on Host Memory and Training-Free Adaptation, 2610.20456v1](https://arxiv.org/html/2610.20456v1), October2026, is particularly relevant to external memory. Root read the method, table-swapping experiments and throughput/late-fusion distinctions. Domain count tables can change at inference without a further gradient update. The main COUNT backbone is pretrained with this input mechanism; tables are built from substantial corpora and can require considerable host memory. Its inference-only late-fusion comparator is a distinct path. This does not show a random model gains all pretrained abilities, and information/storage/lookup costs remain.

### Human algorithm compiled into transformer weights

[Lindner et al., Tracr: Compiled Transformers as a Laboratory for Interpretability, 2301.05062v5](https://arxiv.org/abs/2301.05062v5), November2023 revision, supplies a useful positive control. A human RASP program/compiler constructs transformer weights for bounded algorithmic tasks without gradient pretraining. Information is supplied by the program and instance input. Restricted vocabulary/context and architecture differences limit transfer to learned LLMs; separate compression experiments use gradient descent. Computing a supplied rule is not evidence of acquired arbitrary facts.

### Extra inference computation on a pretrained model

[Lys et al., Inner Loop Inference for Pretrained Transformers: Unlocking Latent Capabilities Without Training, 2602.14759](https://arxiv.org/abs/2602.14759v2), February2026 / March revision, is a plausible wording match. The scout read v1 methods/model setup; root checked v2 abstract/metadata. Repeating selected blocks changes inference computation in already pretrained models. This is no additional parameter training, not absence of pretraining. Modest/model-dependent effects and unstable naive looping constrain extrapolation.

### Strong pretrained builder relocates work into a harness

[Qian et al., AI4AI at Test-Time: Strong-to-Weak Capability Transfer via Harnesses, 2608.12307v1](https://arxiv.org/abs/2608.12307v1), August2026, is a plausible **harness** wording match. A strong builder creates code/routing/format scaffolds for a weaker trained target using validation feedback. No target parameter update occurs, but both models' prior training and builder/harness computation remain. A system improvement does not automatically imply the target's internal reasoning improved or that the gain generalizes beyond the tested tasks.

None of these titles is substituted for the unknown post. They clarify different claims the remembered wording could describe. The most literal theoretical candidate and the closest harness candidate need not be the same paper.

## What transfers to our memory exploration

**Inventory the information route before attributing memory.** The useful question is not just whether weights changed, but whether task information lives in weights, prompts, external tables, code or retained state—and what reader/algorithm can use it. A reset of one route can leave another intact. Effective system performance is different from a model gaining internal factual knowledge.

A proposed known-reader control: keep model code/weights fixed while supplying a correct, cleared, donor or corrupted record. Also test a freshly sampled arbitrary mapping absent from weights, programs and visible records. Distinguish correct execution of a supplied rule from learning new facts. Any statistical claim of information absence needs the stated preparation/access assumptions. No such experiment was run in this scout.

This complements the pending leaky-reset and information-matched predictor designs. It does not replace them or establish a universal theory of memory across all domains. User interest in broad transfer is preserved as a question requiring separate operational mappings.
