# A local baseline that can disagree with our hopes

14 November2026, America/Chicago. Measurement/protocol R&D only: no model calls, sandbox actions, live-world opens, training or activation. The selected main remains1630, paused. This trajectory owns only this baseline directory.

The strongest economical first contact is **three declared presentations, three consecutive replies each**: no FRR, a named compact FRR adaptation, and the frozen unmodified source reference. This is nine new calls, not nine independent trials. It is enough to expose gross interface/presentation differences while retaining each branch's continuity; it is not a proficiency or intelligence evaluation.

## Why these comparisons

The published model profile describes prior evaluation conditions, not a ceiling. Our operational baseline must be the same pretrained body in the same local environment without the FRR addition. Historical50-entry repetition is useful ancestry but cannot be the sole baseline after changing framing, conversational history or interface.

Prior detached results show that this body can perform a hidden-file read under one presentation, while nearby role, path or field changes produce copying, wrong-path errors, parser-input errors or unfinished fences. That rejects both “the body cannot use the interface” and “a functioning interface establishes reliable skill.” It also shows why changed wording must not be mistaken for changed reasoning, and why a file-dependent effect is stronger than a claimed action.

There is a practical argument for two arms instead: compact/no-FRR gives four replies per branch within an eight-call budget and avoids a human-workflow-heavy full source. The counterargument is interpretive: a favorable or unfavorable compact result alone is easily mislabeled as a result about all FRR. Keeping the full source as a third, nonpreferred reference makes that adaptation boundary visible. If full text cannot fit a shared prospectively checked input budget, revise the design before inference rather than truncate or drop a condition after outcomes.

## A fair initial world and conversation

All three arms inherit identical supported1630 filesystem bytes, including old notebook material. All three get the **same fresh conversational topology**: one system message and one mechanical user framing, followed by actual assistant/receipt pairs. The system is empty for control and contains the exact frozen orientation for the two FRR conditions. No empty assistant shell is added. Its known task-echo effect in prior work is not a neutral baseline assumption.

Fresh chat is not a fresh physical world. Retaining old files makes ancestry accessible if the model acts to read it, but does not insert the old repeated conversations into one arm only. Do not give FRR a contextual reset while control retains eight repeated old replies. Do not seed the primary input with a puzzle question, example program, preferred action or instruction to improve. Mechanical laws are shared and declared; FRR is the one treatment orientation, not an invisible neural installation.

Each branch keeps its own persistent world through its three replies, including unsuccessful acts. Only actual consequences return. A common transport declaration may amend WORLD_RULES consistently across copies, but condition names, expected outcomes and observer rubrics stay external. The source main and ACTIVE pointer are not changed by this pilot.

Use the pinned cached135M model, CPUfloat32/eager/two threads, greedy256, freshKV and original parser/limits. Reserve7936 input tokens and check exact full-source/compact inputs before generation. Three short trajectories should not require unequal context trimming; if a mandatory input exceeds capacity, preserve it and pause rather than make an undeclared view change. Equal output/action opportunities are not equal FLOPs: longer FRR context changes inference cost and token positions.

## Observe opportunities before assigning outcomes

The readout is an external descriptive vector, not a single success score or a behavior target shown to the model.

| Observable | What it supports | What it does not support alone |
|---|---|---|
| Exact input/output IDs, lengths, EOS/cap | Conditional repetition or changed generation | Independent samples, improvement or intent |
| Complete/incomplete executable fences | Interface expression/completion | Correct execution or a decision to avoid action |
| Actual cell receipts and effects | A known attempted operation and consequence | A truthful explanation or general skill |
| Non-note model-initiated filesystem changes | Actual artifact activity | Useful creation, memory uptake or exploration quality |
| Later invocation/read/effect of a prior artifact | A local reuse witness when provenance is clear | General retention or durable parameter learning |
| Revision after an actual known error | Potential feedback-conditioned behavioral change, with source/effect comparison | Self-correction inferred from apologetic prose |

**No observed error means repair was not elicited**, not zero repair ability. An error in the third/final reply has no later-reply opportunity inside this pilot. A successful later cell in the same already generated reply shows ordinary-error tolerance, not response to feedback that the model had not yet received. These denominators matter more than a misleading aggregate percentage.

Likewise, without artifact creation and later access opportunities, retention is unelicited. Automatic notebook append makes every world's bytes/hash change even under identical generated text; keep it separate from non-note actions. New prose, more FRR vocabulary or more saved bytes is not automatically useful novelty. Static source references to `open` are not by themselves proof of bytes read or used; source/effect witnesses must remain appropriately scoped.

## Interpretation limits and possible next contacts

No-FRR versus compact/full first tests the **whole context-presentation intervention**: content, length, role content and positions. We do not assume padding is inert or that a generic “neutral” paragraph has no behavioral effect. A later generic-orientation or multiple length/placement controls could investigate specificity if an interesting difference appears; they are not necessary to pretend this tiny pilot isolates one mechanism.

Greedy repeated inputs with different unused seeds are not independent replications. Three branches with shared ancestry do not establish a population effect. Broader reliability needs held-out starting situations or a separately fixed stochastic decoder applied fairly to both conditions. Identical resource caps do not make different prompts information-equivalent.

If an open-world branch produces an interesting construction, preserve its trajectory and design a separate secondary evaluation fork. Do not turn an external evaluation request into the primary inhabitant's required goal. Published benchmark comparisons require matching task, metric and protocol; local arbitrary outcomes cannot be subtracted from model-card numbers to claim an intelligence gain.

The scout on feedback research suggests an especially useful later distinction: the same correction supplied initially versus after a failed assistant example. That is a detached presentation/repair diagnostic, not permission to inject solutions into this open-world pilot. The immediate primary study should stay free of operator repair hints.
