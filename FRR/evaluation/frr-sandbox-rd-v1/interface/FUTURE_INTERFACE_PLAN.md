# Future interface contacts — separate factors before another world redesign

14 November2026, America/Chicago. Plan only; no runs or frozen-input edits. M0/M1 supplied18 replies across six short trajectories with no executed cells. Outputs summarize, copy or invent claims about the descriptions; one conflates a read-only runtime with an unwritable notebook. This is **compatible with an interface/representation difficulty**, not proof of how the model internally interprets the world. Earlier hidden-file reading succeeded under a different presentation, so zero actions here is not zero ability.

**Rank1: initial-only versus truthful live state observation.** This is the closest next contact to an ambient world. Keep the physical filesystem, body, decoder, action grammar, FRR condition, mechanical framing and budget fixed. Compare the M1 initial snapshot with an M2 channel that also returns a directory snapshot after each reply's known effects. Start with a matched no-FRR pair; any later FRR comparison needs that new interface's own baseline rather than reusing M0 as though nothing changed.

The sensor law must be fixed before outputs: names/types/bytes of **all currently supported entries**, initially five, with no highlighted file or suggested action. Do not hardcode five if a model creates a sixth file. Capture after the complete known notebook/cell effects, label initial versus post-reply snapshots and their actual world step, and keep actual runtime receipts separately identifiable. Preserve all snapshots externally. No fabricated observation, success label, novelty bonus, correction or task enters feedback. Choose a full-packet capacity pause or another explicit bounded sensing law prospectively; never silently select “interesting” entries to fit context. Record any necessary descriptive-interface edit without changing physics.

Why useful: successful automatic notebook storage previously returned empty feedback although it changed the world. A live packet makes that change observable without saying “you are wrong” or choosing a next act. Counterarguments: automatic storage is our mechanism, not model-initiated artifact creation; changing numbers and extra prompt length alone may alter generation; more filenames in prose can still be copying. A difference demonstrates a whole observation-channel effect, not semantic understanding or learning. Retain initial-only non-action as a valid result and do not promote live sensing merely because it produces more text.

**Rank2: scoped mechanical prose versus equivalent scoped machine-readable facts.** Test representation with the perception law fixed. Both new arms must explicitly encode the *same* permissions: software runtime read-only, `/world` writable/persistent, processes/tmp transient, and the same action grammar and bounds. Adding writable-world information only to JSON would confound new information with encoding. These common clarifications establish a new local baseline; the old M0 text is historical evidence, not a format-only control. JSON may provoke echoing just as prose may provoke commentary. Length, order, labels and position remain part of the presentation contrast. No question asking the model to recite the laws is required in the open branches; absent assertions leave law-binding unelicited rather than correctly understood.

**Rank3: a separately defined action channel versus fenced conversation.** This is an actuator-law experiment and needs its own baseline before FRR. A possible design separates inert writing from an explicitly committed action payload. Exact encoding, empty/malformed actions and persistence must be specified and mechanically tested first. Merely interpreting every reply as raw Python is not a neutral simplification: it forces prose into execution errors and removes the current thought/action distinction. Do not silently repair, extract or force code, and do not bundle a new port with new sensors or rewards. Counterargument: a new syntax may be less familiar to this pretrained body, so fewer fences is not automatically less cognitive burden.

**Rank4: autonomous world ticks.** A world that changes between actions is a different dynamics experiment, not a description cleanup. Specify update equations, time, no-action behavior, observation latency and pause/resume semantics before any run. Keep its own no-FRR baseline. No hidden energy objective, curiosity reward, competence bonus or required behavior follows from calling it “open.” Static matrices do not already supply these dynamics.

Across all contacts: freeze one factor and exact inputs first; keep branches continuous within their budgets; preserve errors and no-action outcomes; separate supplied observations, attempted acts, actual effects and later reuse. Stopping/reset rules are explicit operational laws, not rewards for pleasing output. Another long identical greedy block is not an independent sample. These ranked contacts are neighboring possibilities, not a ladder the model must follow or a claim that every interface must be tried.
