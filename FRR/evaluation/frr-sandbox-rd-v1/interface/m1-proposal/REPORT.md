# M1 proposal: initial state perception, without a requested action

14 November2026, America/Chicago. Read-only critique and prospective proposal. No model calls, sandbox opens, source edits or M0 metadata changes by this trajectory.

## Recommendation

The proposed M1 contact is useful and consistent with a minimally governed world **as a separately declared perceptual interface factor**. Supplying the names, kinds and sizes of all five actually present files can resemble an initial sensory observation without asking the model to read, solve, create or improve anything. It is nevertheless an intervention, not neutral information and not an FRR repair.

Its rationale follows from a coupling uncertainty, not from a requirement that the model must act. In M0, world files exist but enter immediate input only if a lawful action obtains them. If M1 changes behavior, that would help localize the influence of providing an initial coarse state description. If it does not, that result is retained. Prose-only or action-free output is not a reason to escalate hints.

## Exact proposed setup

`initial_sensor_packet.txt` serializes the complete five-file names/types/bytes manifest from the common **pre-model M0 snapshot**, after its clean rule-description replacement. This is authoritative captured filesystem metadata, not a fabricated `ls` output or model-originated receipt. Its captured world ID and source hash are in SPEC.json.

Each fresh M1 branch starts from that same physical snapshot and uses the same M0 mechanics, rule bytes, body, decoder and frozen control/compact/full system contents. Append the exact packet once to the initial mechanical user message, separated by two newlines. No natural-language suggestion, file highlight, target question, command, answer or score accompanies it. Observer provenance is kept outside the model-facing packet; the actor label `operator` is not required as another prompt cue.

The packet is tagged as an **initial_directory_snapshot**. Its initial notebook size will become stale after the first append; it must never be relabeled as live/current or repeatedly refreshed to steer attention. Keeping that original initial message in subsequent context is not a new observation. Future state acquisition, if any, belongs to the model's own lawful actions.

Do not inherit a final M0 branch: those contain different model writing and would confound the initial-state comparison. Do not clean the notebook or prior replies to make M1 look simpler. Do not change the world rule file just to advertise an observer experiment. The existing common physical state already supports this observation; no new physics is needed.

## What this can and cannot show

M0/M1 crossed with three system presentations yields six condition trajectories. The three turns within each are dependent, not independent samples. M1 was considered after seeing the M0 no-action pattern, so this is adaptive exploratory design; it is not a confirmation protocol frozen before M0 results.

File names, their meanings, sizes, ordering, JSON vocabulary, added input length and location may all contribute. A correct filename appearing in prose can be supplied-text copying. Active file acquisition requires actual executable operations and their receipts; useful use, retention and transfer are further distinctions. An interaction between FRR presentation and M1 would be an observed interaction in this small setup, not evidence for one uniquely identified FRR mechanism.

The most important safeguard is conceptual: **no human target does not mean no engineered interface**. A coarse sensor packet is a designed observation channel. That is compatible with the user's goal if explicit and shared, but should not be hidden under the phrase “simply let into a world.” The direct alternative—continuing M0 unchanged—is also legitimate, although identical deterministic input/output cycles may add little new information.

## Verdict

Proceed only as the separate M1 condition if root chooses it, preserving M0 and the main1630 checkpoint. Freeze exact packet and full conditions before new outputs. Use ordinary consequences without coaching; retain all failure/non-action outcomes. Do not select M1 as the main-world perception law merely because it produces more text or a first executable cell.
