# Cycle 3 — final agency review

Read `DESIGN.md` and all three available Cycle 2 reviews in full. Research/design review only; no new search, implementation, model execution, or primary-world access. Client date: 5 November 2026; host UTC: 6 November.

**Assessment:** the design preserves the intended computational freedom. Procedures, text, lists, explicit state transformations, immutable dependencies, and ordinary stored drafts permit varied constructions without a task catalog. It resolves the assembly/interface mismatch and distinguishes completed chunks from saving an exhausted VM. Optional seeds are explicitly ignorable; construct/repair/reuse walkthroughs refer to actual executable effects rather than explanations. Small-model competence and persistent-memory benefits remain unclaimed. Deferring closures, dynamic execution, and concurrency narrows convenience without turning the world into a scripted curriculum.

## Exact corrections before calling the contract settled

1. **Resolve publication in §§2–3.** “Successful output can be published” and a commit that publishes before reporting success still permit two readings. Specify `run -> COMPUTED` with a bounded staged-result ID, followed by `publish -> PUBLISHED`, or specify a declared `run-and-publish` mode. A computation should not silently rebind a project alias. Failed publication must leave the computed/published status unambiguous. These are agent actions, not permission dialogs.
2. **Finish storage agency in §§2–4.** Immutable revisions and no silent deletion are sound, but a full store currently leads only to refusal. Specify agent-visible quota inspection plus explicit deletion/archival/compaction behavior, including pinned dependencies and whether history is still replayable. Host receipt reserves and guest construction bytes must be separate. Unlimited history is unnecessary; an explicit ability to choose what to retain matters.
3. **Make seed conditions operational in §§4 and 6.** State that no-seed runs lack seed artifacts/aliases as well as seed prompts. Log continuing seed timing, wording, whether requested, and acceptance/decline; do not score compliance as curiosity. After competence checks, provide a separately identified open-choice period with no compulsory target. A fixed onboarding ladder is an interface check, not the world's ongoing curriculum.
4. **Clarify parameters in §1.** Replace “explicit named arguments” with “explicit parameters and positional arguments” if keyword arguments are not intended. State how an agent finds callable signatures and retrieves a bounded dependency/source view; stable IDs without usable discovery would leave practical freedom below theoretical expressiveness.

## Remaining uncertainty and next step

Nothing yet establishes that 135M+LoRA can reliably retrieve signatures, supply bounded structured inputs, repair nested expressions, or plan successful checkpoints. Pure state passing can express continuing instruments and simulations, but may impose more bookkeeping than this model handles. Displaying structured text/grids could make consequences easier to inspect; a renderer should remain a separately specified, bounded presentation facility rather than a prerequisite for broadening the kernel.

Next produce a short operational specification containing the value/expression grammar, action/status table, artifact discovery and quota rules, exact publication choice, and one complete transcript each for construction, counterexample-driven repair, dependency-pinned reuse after context reset, and successful chunk continuation versus exhaustion. Include seed-free and seeded initial snapshots. Resolve these points before implementation; then test host semantics and isolated model usability separately. Report improved external-library use as such, with fixed base and LoRA weights, rather than as spontaneous learning or curiosity.
