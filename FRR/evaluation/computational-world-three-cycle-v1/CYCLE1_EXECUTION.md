# Cycle 1 — bounded persistent execution scout

Recommendation: implement one small, explicit, deterministic bytecode interpreter over a persistent symbolic store. Give programs conditions, jumps, subroutines, and indexed memory; bound every invocation and every allocation. A fixed 135M model with LoRA can then author and reuse algorithms without receiving a shell, Python `eval`, native modules, or ambient filesystem authority. This is a design inference, not a claim that these sources establish model competence.

## Primary evidence and read depth

Read on 5 November 2026 client date (host UTC 6 November). Four source groups; no installs, model execution, paid calls, or external writes. GitHub connector was preferred for repository materials; official web pages supplied the language and database sources. Runtime skill and current network policy inspected; managed environment reported unrestricted HTTP, no configured identities/secrets, VPN false.

1. **Software Foundations, Logical Foundations, [ImpCEvalFun](https://softwarefoundations.cis.upenn.edu/lf-current/ImpCEvalFun.html).** Read evaluator definitions, option-valued exhaustion handling, explicit index warning, and relational equivalence/monotonicity statements through the final determinism theorem (entire chapter; one converse proof is an exercise). Fuel makes the evaluator total without making the underlying `while` language terminating. The example's index is a recursive-depth bound: sequencing passes the same decremented index to both calls. It therefore is not an exact count of executed transitions. Success and exhaustion need distinct results. This supports the approach, but does not prove our proposed interpreter correct.

2. **Wasmtime official [interruption guide](https://github.com/bytecodealliance/wasmtime/blob/main/docs/examples-interrupting-wasm.md), [fuel example](https://github.com/bytecodealliance/wasmtime/blob/main/examples/fuel.rs), and [Config API](https://docs.wasmtime.dev/api/wasmtime/struct.Config.html#method.consume_fuel).** Read whole guide/example and API sections `consume_fuel`, epochs, blocking host calls, and variable-size operations. Fixed fuel gives deterministic interruption when execution has no other nondeterminism; epochs depend on timing. A trap is not resumable; asynchronous yielding is a different mechanism. The API warns that reported fuel consumed after traps is imprecise and recommends not reusing that Store for exact accounting. Neither fuel nor epochs handles a guest blocked in a host function. These are metering mechanisms, not a wall-clock or host-work proof. The live API is development documentation (52.0.0-dev), so production use would require a pinned release and verification.

3. **Wasmtime official [security document](https://github.com/bytecodealliance/wasmtime/blob/main/docs/security.md).** Read whole document, especially WebAssembly Core, Filesystem Access, Terminal Output, and defense-in-depth. Guest memory accesses are bounded; control transfers are checked; interaction occurs through explicitly linked interfaces. WASI filesystem access uses capabilities. The document also acknowledges implementation bugs and mitigations. Imports define authority: linking a host function can confer effects beyond symbolic state. Escape-containing output needs safe rendering. Sandbox isolation supplies neither durable commit semantics nor application-level authorization rules.

4. **SQLite official [transaction semantics](https://www.sqlite.org/lang_transaction.html).** Read all transaction, explicit/implicit commit, locking, and error sections. Transactions allow grouping writes; only one writer proceeds at a time. Some errors undo one statement while preserving earlier writes; others can roll back the transaction. Explicit rollback normalizes application error handling. A failed COMMIT can leave a transaction active. Therefore never equate a guest trap, Python exception, or failed database operation with a completed atomic rollback/commit. This source is a persistence reference, not evidence that an event log automatically replays deterministically.

## Minimal proposed machine (engineering inference)

**Language.** One text assembly syntax and one canonical parsed representation. A finite instruction set: integer constants, load/store, add/subtract, comparison, conditional/unconditional jump, indexed read/write, call/return, `emit`, and `halt`. Fixed signed 32-bit arithmetic with explicit overflow error initially; no floats, dynamic imports, host object references, OS paths, or arbitrary host expressions. Indexed storage plus data-dependent looping permits search, sorting, traversal, state machines, and simulation within quotas. A small compiler or parser is host code; no learned component adjudicates execution.

**Configuration.** `(program_id, pc, value_stack, call_stack, heap, staged_world_delta, staged_output, fuel_left)`. `step` validates operands/addresses, checks capacity and cost, then performs exactly one instruction. The runner iterates `step` rather than recursing through the guest AST. Every executed instruction consumes one unit; variable-size operations are absent initially. A later copying/query primitive must charge by work/bytes or be decomposed into resumable elementary transitions. Parsing, validation, hashing, serialization, storage operations, and observation generation have independent size/work caps: instruction fuel alone cannot bound them.

**Initial limits to measure, not benchmarks.** At most 256 instructions/program, 4,096 integer cells, stack/call depth 64, 10,000 executed instructions/invocation, 1 KiB emitted output/invocation, and a separately capped durable store/run ledger. These constants are provisional CPU-friendly test settings. Bound submitted text bytes and nesting before parsing. Reject oversized values before allocation. Add an external wall-clock/process memory watchdog for interpreter bugs; watchdog events are `HOST_ABORT`, excluded from deterministic task scoring and never committed as success.

**Authority.** Guest instructions address only a world namespace supplied by opaque logical IDs and access rights. A guest cannot open host files, access environment variables, call the network, or invoke a command. Store authority is implemented in the interpreter, not via trusting guest names. Serialization and output are data, rendered escaped. If stronger adversarial isolation is later required, put this host-owned interpreter in a constrained worker process; do not claim that writing a custom interpreter proves exploit resistance.

**Atomic invocation.** Execute against a frozen world version with an in-memory staged delta. `HALT` plus schema/quota checks permits a host transaction to write delta, new world version, program identity, and execution receipt together. `PARSE_ERROR`, `TYPE_ERROR`, `ADDRESS_ERROR`, `ARITHMETIC_ERROR`, `OUT_OF_FUEL`, and capacity errors discard staged mutations and staged public output. Retain a bounded diagnostic receipt outside world state. Check storage commit success before reporting `COMMITTED`; explicitly roll back on storage errors. The simplest implementation is serialized execution with one host-owned SQLite writer, no exposed SQL and no distributed transaction machinery.

**Durability and replay.** Persist program bytes/hash, interpreter version, opcode/cost version, initial world version/hash, explicit inputs, limits, outcome, final hash, and a bounded trace summary. Retain snapshots plus canonical action records under a documented quota. Replay means re-execution from the recorded snapshot with the pinned semantics; a matching hash is a check, not a proof. Avoid clock, ambient randomness, concurrent writes, and unordered traversal. If randomness is needed, make a fixed PRNG seed and algorithm explicit inputs. No checkpoint/resume in v1: exhaustion rolls back, and the next invocation reruns. Saved programs and world artifacts persist independently of model context.

## Three strongest implications

1. **Count a specified operation, not an evocative token called fuel.** A single shared monotonically decreasing transition budget plus bounded-value instructions is easy to audit. Recursive-depth fuel, guest opcode count, host CPU time, and model token count are different quantities. Report exact interpreter transitions, outcome, and caps; do not translate them into exact CPU work.
2. **Persistence expands useful composition, not authority.** The model may build named algorithms and data structures across turns while all effects remain inside the world. Atomic staged writes make failed attempts inspectable without silently corrupting shared artifacts. Meter and cap persistent storage as carefully as per-run memory, including failed-run logs.
3. **Wasm is a reference and optional later substrate.** Its import boundary and fuel design validate the conceptual separation of capability, metering, and host behavior. A Wasm compiler/runtime, WASI setup, async resumption, and full instruction debugger add avoidable complexity for this initial small symbolic world. Introduce Wasm only for a measured need for existing compiled languages or execution performance.

## Expressiveness and observation limits

- Any deployed machine with fixed program/storage/value bounds has finitely many configurations. It is not literally an unbounded universal computer. A language with jumps/loops can express nonterminating programs in its idealized semantics; bounding an invocation guarantees return of a status, not eventual success, general halting decisions, or completion within a budget. Increasing limits changes the operational experiment.
- `OUT_OF_FUEL` means no normal halt was reached within this budget. It does not mean divergence, invalid algorithm, or lack of a solution. Complete bounded machine-state cycle detection could sometimes certify a loop, but is unnecessary and potentially expensive in v1.
- Define an observation contract before training: e.g., outcome + exact transitions used + committed world version + up to 1 KiB output + explicitly requested paginated cells. Return `truncated`, total items/bytes when known, and continuation cursor. A hash or summary does not expose full state; hidden cells must remain queryable under bounded observation actions. Count those actions and bytes in evaluation.
- A bounded trace proves only the recorded prefix; a final-state hash alone cannot diagnose intermediate mistakes. Host audit may store a bounded full trace for tiny runs or reproduce the full run deterministically. The model sees only its declared observations, never the host audit log by accident.
- Long-lived records do not establish that the model knows, remembers, or generalizes their contents. Evaluate artifact retrieval, reuse, correction, and composition separately from short-run execution success. No cited source establishes that a 135M+LoRA model can reliably program this proposed ISA; that requires the later controlled experiment.
