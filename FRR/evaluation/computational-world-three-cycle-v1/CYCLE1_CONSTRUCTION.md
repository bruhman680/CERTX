# Cycle 1 — construction, libraries, and computational worlds

Research only; inspected primary texts/code through web and GitHub tools. No installation, model execution, or primary garden access. Target: a fixed CPU 135M+LoRA language model composing executable artifacts in a persistent computational world, with optional concept seeds and auditable effects.

## Four strongest inspected sources

**1. Papert & Harel (1991), [Situating Constructionism](https://web.eecs.umich.edu/~mjguz/csl/home.cc.gatech.edu/allison/uploads/4/papert91.html).** Primary essay on an institutional mirror; read opening argument and research qualifications (lines 0–26), not the entire volume. Original papert.org endpoint timed out. Constructionism emphasizes building a public entity and accommodates different styles of working with concrete materials. Transfer: make executable, inspectable objects the medium—programs, diagrams, transformations, little instruments—with a visible history that supports revisiting and discussion. Optional seeds can invite projects without prescribing one correct construction. Attribution limit: this is a theory/research agenda about human learning, not evidence of persistent-memory learning, curiosity, or developmental transfer in a frozen language model. Evaluate the system's actual revisions and artifact reuse rather than borrowing the human-learning conclusion.

**2. Papert (1977), [Notes on the Future of Logo](https://dailypapert.com/notes-on-the-future-of-logo/).** Read complete short transcribed meeting notes (main text lines 28–59); original scan is linked but was not inspected. Papert singles out easy procedure definition, procedural organization, and the combination of action-oriented turtle graphics with procedures. He advocates flexible, modifiable, extensible language systems, while criticizing feature accumulation as a substitute for a good language. Transfer: choose a small coherent primitive set, named procedures, composition, and immediate execution feedback. Permit multiple computational media through the same procedure mechanism rather than imposing plant-specific verbs. Evaluate whether a seed becomes a modified or recombined procedure, and whether feedback leads to a meaningful repair. These notes express design judgment and educational claims, not a controlled causal study or a specification for machine intrinsic motivation.

**3. Ellis et al., [DreamCoder](https://arxiv.org/html/2006.08381) (arXiv v1, 2020; later publication versions differ).** Inspected introduction and wake/sleep methods, especially lines 53–74 and algorithm equations; did not reproduce results or read supplementary implementation details. Waking searches for programs satisfying supplied tasks. Abstraction sleep extracts reusable code to improve a description-length/Bayesian objective. Dreaming trains a recognition network on replayed and sampled program/task pairs. Transfer: retain tested procedures with dependencies and provenance; allow a later construction to invoke or refactor earlier code. Measure successful reuse and shorter solutions on new inputs. Essential limit: DreamCoder's improvement comes from explicit outer search, library optimization, supplied task distributions, and neural training. A frozen 135M+LoRA agent with stored code has an external library, not DreamCoder's trained recognition improvement. Automatic abstraction, candidate selection, and task generation must each be logged as separate contributions. This paper does not establish autonomous curiosity from persistence.

**4. Avida, [default environment configuration](https://github.com/devosoft/avida/blob/master/avida-core/support/config/environment.cfg), blob `083a1a997f76808fab7999bf9e0d16bea5ca8522`.** Inspected complete configuration through GitHub plus repository README; inspected neither execution engine nor a run. The configuration explicitly associates nine Boolean computations with reaction values and a one-count requisite; comments identify an undepletable resource. Useful because the world substrate and selectable consequences are directly computational and inspectable. Transfer: give programs concrete inputs, outputs, state transitions, and resource costs; record exactly which rule caused each consequence. Attribution limit: configured payoffs are designer incentives, not discovered interests. Biological names or evolution alone do not make a world open-ended. Ofria & Wilke's [2004 platform paper](https://doi.org/10.1162/106454604773563612) was located, but full-text fetches failed; no paper-method claims are inferred from its abstract. Avida is an auditability precedent, not a proposed reward scheme or evidence about a fixed language model.

## Design and evaluation implications (our proposals, not source results)

- Provide one persistent workspace containing executable procedures, structured data, rendered artifacts, and notebooks. A bounded deterministic interpreter should expose generic arithmetic, lists, grids, events, drawing, and composition; prioritize a compact callable vocabulary that the small model can use. Finite compute limits do not require a finite list of permitted projects.
- Every action should return an observable delta: inputs, output/error, changed objects, dependencies, elapsed steps, and the invoked rule. Snapshot and replay the same initial state/action sequence. A named object without an executable or inspectable consequence is weak evidence of construction.
- Treat concept seeds as removable invitations (e.g., repetition, feedback, symmetry, communication), never hidden success labels. Compare no seed, minimal seed, and richer seed with matched interaction/compute budgets; report seed content and intervention frequency.
- Separate **artifact accumulation**, **retrieval-assisted performance**, **within-context adaptation**, and **parameter learning**. With base and LoRA weights fixed, the last is absent. Use a fresh context with an intact library, a fresh context with the library removed, and an intact library with matched irrelevant material to distinguish useful persistence from extra context or evaluator scaffolding.
- Audit causal chains: which program created an effect, which observation preceded revision, and whether a later artifact actually invokes or transforms prior work. Test retained components on held-out inputs and measure compute-normalized successful compositions, correction after counterexamples, dependency depth, and executable diversity. Counts of filenames, tokens, or declarations of curiosity are insufficient.
- Keep reward/search variants explicit. If an outer process filters candidates, awards novelty, generates tasks, or promotes abstractions, compare against its removal and attribute gains to the combined system. Persistence is an affordance whose value must be demonstrated; it does not establish spontaneous learning or interest.

Cycle 2 review target: assess whether the proposed interpreter is usable at 135M scale without collapsing into a scripted task menu, and whether the persistence ablations isolate causal reuse under equal token/compute budgets.
