# Cycle 2 — execution semantics cross-review

Research date: 5 November 2026 (user-facing); host UTC date: 6 November 2026. Reviewed `CYCLE1_PRIMITIVES.md`, `CYCLE1_CONSTRUCTION.md`, and the execution scout. Research/design only; no implementation, model calls, installs, or primary-world changes. No additional sources were necessary; the existing [Software Foundations evaluator chapter](https://softwarefoundations.cis.upenn.edu/lf-current/ImpCEvalFun.html), [Wasmtime interruption semantics](https://github.com/bytecodealliance/wasmtime/blob/main/docs/examples-interrupting-wasm.md), and [SQLite error semantics](https://www.sqlite.org/lang_transaction.html) directly constrain the repairs below. Counterexample traces and repairs are our engineering inferences.

The other scouts improve the proposal: use a compact Lisp-like authoring surface, retain an explicit transition machine beneath it, and persist inspectable source/dependencies rather than only opaque execution objects. The unresolved issue is a single contract spanning execution, durable versions, and observations. Three concrete failure traces expose it.

## 1. A failed invocation accidentally becomes an unbounded paused computation

Initial committed version `w7`: durable `counter=0`; `tick` repeatedly increments it. Run budget is 3 transitions. A naïve evaluator writes increments immediately, then returns `OUT_OF_FUEL` with `counter=1`. The next action says `resume`; another increment commits. Repeating bounded actions eventually produces arbitrary cumulative work and durable partial effects, although the evaluator labeled each invocation a failure. A second implementation instead rolls back `counter`, but preserves a continuation holding its staged `counter=1`; resuming against changed `w8` can overwrite a legitimate intervening edit. These are observably different languages under the same status name.

**Repair:** v1 has exactly one atomic invocation: `HALT` permits commit; every guest error or exhaustion discards staged writes/public output and destroys its continuation. An `OUT_OF_FUEL` receipt may show a bounded diagnostic prefix marked uncommitted. A retry starts from a named committed version with a fresh run budget; total episode fuel/actions must also be bounded and reported. Longer work can be expressed as deliberate successful chunks that explicitly store algorithm progress, each ending in `HALT`. The next chunk consumes that visible progress as ordinary data; it is not implicit continuation resumption.

If pause is later required, give it a distinct `PAUSED` result and a versioned, quota-charged continuation object, with pinned source/dependencies, captured base world version, remaining total job allowance, and an explicit conflict/cancellation rule. Returning from a bounded call then does not mean the *job* finished. Wasmtime's trap versus asynchronous-yield distinction is a useful precedent; a trap must not be presented as resumable.

**Remaining decision:** adopt rollback-only v1, or support explicit chunking examples in the seed library. Recommended: rollback-only execution plus one inspectable chunking example in a separately labeled seeded condition. Do not implement transparent pause yet.

## 2. Failed writes consume all space needed to report failure

Durable cap is 1,000 bytes; the world occupies 980. `make` stages a 30-byte artifact; evaluator correctly rejects it with `DURABLE_QUOTA`. The host then appends a 40-byte failure receipt to the same capped store: either it violates its own quota or cannot record/return the reason. After repeated failed attempts, a supposedly rollback-safe system has an exhausted log. Separately, a 10 KiB trace and JSON encoding may be allocated before the output cap is checked. That makes a 1 KiB observation limit irrelevant to peak memory. An automatic retry of COMMIT following a timeout can also duplicate receipts unless action identity is explicit.

**Repair:** distinguish world bytes, pending mutation bytes, transient allocation, per-response bytes, and audit-ledger bytes. Check estimates before constructing large strings/collections, then enforce exact canonical serialized size before commit. Reserve a fixed maximum receipt slot before admitting an action; guest code cannot spend it. Write successful delta + version + action ID + receipt atomically; record a failed receipt in a separate small host transaction after discarding staged effects. Failed receipts have fixed bounded fields and bounded diagnostic samples, never unrestricted guest text or traces. A duplicate action ID retrieves the recorded result rather than executing again.

The audit ledger itself has a hard episode budget. When no receipt can be admitted, stop accepting further actions with a fixed host status; retain the existing ledger. If longer operation is desired, predeclare snapshot/export and retention policy. Silent eviction prevents exact historical replay and must not be advertised as permanent retention. Replay claims cover only retained snapshots and records. Storage failure must return `HOST_STORAGE_ERROR` or unknown commit status reconciled by action ID, never fabricated `COMMITTED`/`ROLLED_BACK` certainty. SQLite may preserve earlier statements after some errors, so the host explicitly normalizes rollback and checks commit result.

**Remaining decision:** fixed ledger then terminal `EPISODE_FULL` is simplest for the finite experiment. Specify whether audit-byte costs count against the agent's experimental resource budget; recommended: all conditions receive the same preallocated host reserve, while guest-visible world capacity remains separately matched.

## 3. One cheap primitive and a mutable library name break both metering and replay

World `w4` contains `s` with 4,096 characters and `score@1`, which returns list length. Program `p@1` calls the name `score` and computes `equal?(concat(s,s), concat(s,s))`. An evaluator charges one unit per surface operation, although concatenation allocates/copies thousands of bytes and equality scans them. Repeating this pattern can monopolize host work inside a single nominal step. A later seed update changes `score` to `score@2`; replay of `p@1` resolves the current name, changing the result, dependency cost, or side effects. A rendered artifact built from `score@1` can now falsely appear to derive from `score@2`. A "no seeds" run that still resolves host-seeded names is contaminated even if its opening prompt omits the seed text.

**Repair:** surface forms compile/evaluate into a specified machine with explicit left-to-right order and transition accounting. Meter evaluator dispatch, calls, allocation, and size-dependent work. For v1, either bound operands tightly enough that a primitive has a declared maximum host cost, or charge length/work before executing; decomposition into elementary transitions gives the clearest interruption points. Charge multiplication by bounded operand width or use checked fixed-width integers; text operates on an explicitly chosen encoding/index unit. Bound parser depth/input bytes and source serialization independently. Exact reported transitions are exact under this machine, not exact wall-clock cost or Wasmtime fuel consumption after traps.

Every durable object/program has an immutable version ID and canonical content hash; names are separately versioned aliases. Definition publication captures lexical dependency bindings (`p@1 -> score@1`), including mutually recursive groups as one bounded module where needed. Executing an artifact supplies a frozen world snapshot. Dynamic lookup is absent initially; if later permitted, log the resolved version as an input. Pure program identity and execution input world identity are distinct. Object mutation creates a new version; artifacts record creator run ID and source/dependency versions. Keep version history under an explicit storage/retention quota.

Seed installation is a logged initial-state intervention, not an invisible host library or special evaluator behavior. Seeds are ordinary inspectable definitions and data subject to the same runtime rules. The no-seed initial snapshot lacks their definitions, artifacts, aliases, and seed-only tools. Shared language primitives remain identical. Track seed bytes and retrieval/context cost separately; matched compute does not by itself equalize the substantial information supplied by a seed. Deterministic randomness, if used, is a separate explicit PRNG state/input and should not be confused with concept/library seeds.

**Remaining decisions:** exact text representation and cost table; whether procedure closures are serializable; alias rebinding rules; and how to retain old dependencies without exhausting storage. Recommended v1: immutable named top-level procedures with explicit captured definition bindings, no arbitrary durable closures, bounded UTF-8 byte strings with byte-indexed operations, and a pinned versioned cost table. If the authoring surface keeps lexical procedure values, transient closures are allowed but durable publication must materialize inspectable closed dependency records or reject unsupported capture.

## Joint recommendation to carry forward

Freeze a single operational contract before a model experiment: Lisp-like surface; explicit deterministic evaluator; atomic rollback on exhaustion; successful explicit chunks for long tasks; immutable program/object versions; bounded charged bulk operations; preallocated receipt reserve; and a fully specified observation/pagination contract. Keep grid/events/drawing as ordinary data plus a small deterministic renderer or later library, rather than adding numerous unmetered host services. Rendered output has its own dimensions/byte/operation caps and provenance. Each added medium should demonstrate a real construction the kernel cannot already express conveniently.

A finite per-action budget does not bound an unlimited episode; persistent artifacts do not imply unlimited history; a returned summary is not a full-state observation; and a frozen model's improved library use is not parameter learning. Record all four boundaries in the evaluation protocol. The proposed constraints still allow meaningful algorithmic construction; whether 135M+LoRA can use the surface remains an empirical question rather than an execution-design result.
