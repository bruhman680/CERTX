# HG1-L1: one-case authored handoff smoke pilot

Prospective scope: LINEAR-2 only, four arms, one trajectory per arm. Two writer turns in the same context, then one fresh reader per handoff: maximum 12 model completions. This narrows the proposed 48-completion pilot to the task covered by the checked instrument; it does not launch the larger draft. Task, arm operations and source keys were previously exposed. This is a workflow development contact, not independent confirmation or a general effectiveness experiment.

Each writer begins with fork_turns=none, inherited model and effort, common schema/access instructions, assigned first-arm text, and exact case. Stage two continues that context with the saved second-arm prompt and no scoring feedback. No answer keys or future updates assigned. Readers begin fork_turns=none with common reader instructions, the final handoff and the frozen continuation update only. Reviewer agents are not reused. Model sampling settings and actual token/dollar usage are unavailable and must be recorded as unknown. No provider API calls. Context lineage and raw prompts/outputs retained.

Assigned access: no tools or external sources for actors/readers, only supplied text and previous same-writer turn. Tools/filesystem remain physically accessible; this is instruction-based access, not enforced isolation. Any visible tool calls/access deviation invalidate clean packet-only interpretation and must be retained. No retry for wrong, malformed or oversize output. Host infrastructure failure ends the affected trajectory; all attempts count toward 12. New actor/reader contexts do not establish independent model provenance.

All arms use the same structured writer format: answer plus handoff. Handoff contains explicit linear equality facts and optional note. This changes the task into a structured-certificate development pilot and may make information preservation easier than prose. Facts may be equivalent compressed equalities; raw-copying is not required. No imposed minimum content. Handoff request <=180 whitespace-separated words of its canonical JSON serialization (sort_keys=True, ensure_ascii=False); violation recorded, no truncation or repair. No hard token cap enforceable by collaboration tool. Stage-one draft retained but only final handoff sent to reader. Reader receives no source equations separately. All task-domain assumptions must survive in the handoff note if needed; no neutral shell adds missing source facts. This task's target with b=3 is checked using equalities only.

Arm order is a fixed shuffle using Python random.Random(1847) of ordinary, continuation, functional, hpgm, pinned in SETTINGS.json. Launch actors/readers in that assigned order; host scheduling is not experimentally controlled. Functional versus HPGM differs only specified headings, not body operations. First and second prompts plus common additions frozen in SETTINGS.json. Reader sees anonymous trial ID, not arm name. Preserve handoff exactly; no label stripping or content normalization. If note discloses the condition, mark reader as potentially unblinded.

Evaluation: exact structured scorer version0.1 for LINEAR-2. Reader status/value/support IDs are joined to exactly supplied facts, without adding omitted original facts. Report objective correctness, packet support, source validity, grounded completion, appropriate abstention separately. Invalid schemas are parse failures, not silently repaired responses. Scorer origin checks are against fixed authored source, not a certificate that the model used the evidence. Audit source/model outputs for unsupported prose claims separately; automated equality checks do not validate the note or nonnegativity constraints.

Writer initial answer audit: nonidentifiability of a+c requires at least two distinct nonnegative assignments satisfying original equations with different a+c. Accept any such witnesses. Record a false uniqueness claim, invalid witnesses, factual handoff corruption, and format/length failures separately. Score first/final writer outputs; no answer repair fed back. An absent/null value for an underdetermined quantity is expected, not a missing forecast.

Primary descriptive counts: final writer correctness and reader grounded completion by arm. Secondary: draft-to-final changes, valid/source-faithful retained equalities, actual handoff size, missing/unsupported reader answers, packet-only access adherence, parse/length failures. Outcomes include ties, worse checkpoints, and label neutrality. No significance test, winner, optimal-stage claim, FRR efficacy or equal-compute claim. Ceiling success is a limitation and can terminate this smoke pilot rather than justify claiming benefit.

Freeze this protocol, settings and referenced source/scorer hashes in LAUNCH_MANIFEST.json and commit before first writer output. After all outputs, save launch-hash recheck, per-trial audit and full raw records. Evaluator repairs retain original outputs/judgments, version corrections, and rescore affected cases consistently. The six preceding reviews and 18 constructed scorer controls are preparation, not behavioral samples.
