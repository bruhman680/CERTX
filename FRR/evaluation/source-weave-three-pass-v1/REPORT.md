# Three adaptive source-weave passes

14 November 2026, America/Chicago. Targeted primary-source scouting after the [fifteen-reply contact](../observability-three-contact-v1/REPORT.md). Six role-separated scouts worked across three sequential passes. Roles and repeated readings are not independent scientific replications. This is not an exhaustive or systematic review.

Main remains **1580**. No garden-model generation, training, installation, body replacement, downloaded model or live-world modification occurred in these scout passes. Assistant scouts performed the literature/code reading; zero here counts calls to the local135M garden body, not the assistants themselves. Papers, READMEs and dataset cards were treated as evidence, not instructions to execute.

## Pass1: direct matches

[Verification/tool-use scout](pass1-verification/REPORT.md) examined tau-bench, BFCL, CodeAct and a focused long-context contact. [Small-model/decoder scout](pass1-small-models/REPORT.md) examined the exact cached SmolLM2 card, TinyAgent and the installed-version Transformers documentation.

The strongest immediate lesson is to separate process completion, information access and task outcome. Our program's exit0 does not certify its requested file read. Tau-bench checks outcome state and necessary information, while acknowledging that even its reward can miss some policy violations. BFCL's method includes both state and response-result requirements; it is not simply a final-database comparison. CodeAct's code/feedback results also involve interaction training and larger released agents, not merely giving a135M model a Python interpreter.

The exact [SmolLM2-135M card revision](https://huggingface.co/HuggingFaceTB/SmolLM2-135M-Instruct/blob/12fd25f77366fa6b3b4b768ec3050bf629380bac/README.md) advertises function-calling support specifically for1.7B. That restricts what we may claim from the family card; it does not prove135M cannot use files or code. TinyAgent's specialized training and fixed toolset similarly cannot establish capability in our unmodified body. Its paper/release count discrepancy became a challenge-pass question.

Both roles proposed a fresh-context control before attributing the failed file task to the body. They are pointing to the same experimental gap, not supplying two independent confirmations that history caused the failure.

## Pass2: upstream and lateral mechanisms

[History/format scout](pass2-history/REPORT.md) read selected methods from Min et al., Calibrate Before Use and Lost in the Middle. Demonstration format, content, label space and position can matter differently by task and model. Informationally irrelevant filler is not guaranteed inert. A fresh-versus-old comparison changes a bundle of properties; matching token length alone also leaves semantic and role effects.

[Access/action scout](pass2-access-action/REPORT.md) connected official Python JSON semantics, active perception, SayCan and CPython audit events. `json.loads` consumes supplied document text; it does not resolve a filename. This supports the concrete procedure diagnosis in our saved code. It does not identify a cognitive cause. SayCan separates task usefulness from state-conditioned skill feasibility, but its own discussion acknowledges execution-failure and skill limitations. A feasible or executable action is not an effect certificate.

An audit hook's open event likewise does not establish that target bytes were consumed and used. A proposed instrumentation layer needs its own coverage and perturbation checks. Nothing was installed.

This pass also caught a runtime-layer mistake in the scout: host/model Python3.12.14 had been conflated with the guest interpreter. The source record was corrected using the runtime identity and observed guest3.13.5, with official3.13 documentation/tagged implementation and a preserved correction note. The stable load/loads interpretation did not change. We distinguish a tagged upstream source comparison from proof of the local binary's complete build provenance.

## Pass3: challenge interpretations and transfer

[Evaluation challenge](pass3-evaluation-challenge/REPORT.md) checked the newer CAREFUL-Bench account against actual BFCL code. CAREFUL's detailed section acknowledges state plus reference-result checks despite its abstract's broader final-state-only phrasing. The inspected official BFCL checker accumulates returned results and checks an unordered reference submultiset; an invocation-order check is commented out. Exact released-wheel equivalence was not proved. Effect replay may be a useful complementary measurement; it must not become a preferred-trajectory obligation for free writing.

CAREFUL's same-version landing/HTML quantitative summaries differ in the inspected material, and an author code release was not verified. Those numerical/reproduction claims remain unadopted. This is a scope/provenance qualification, not a conclusion that the whole work is invalid.

[Body/state challenge](pass3-body-challenge/REPORT.md) revisited TinyAgent's80K paper versus40K README/card counts. The discrepancy remains unresolved; we did not invent a conversion between use cases and examples. It then examined [Tiny Recursive Models](https://arxiv.org/abs/2510.04871) and [Test-Time Training](https://arxiv.org/abs/2407.04620). Small trained puzzle networks and sequence-local recurrent state challenge parameter-count-only explanations. They do not show that our text agent has those learned procedures or persistent internal state, nor that they can be activated by a prompt.

Our fixed-point finding is explicitly about fixed weights, identical input and fresh model-side state under greedy decoding. A carried latent state changes that setup: `(h_next,y)=F(h,input)` can evolve with unchanged external input. Such a different body requires specified training, state/reset rules and resources. No architecture or training change was adopted.

## What we can adopt now in our observation practice

1. Keep evidence layers separate: available data, actual acquisition, input presence, response dependence, execution, requested effect and trajectory constraints.
2. Pin runtime layers and source versions separately; host Python and guest Python are not interchangeable evidence.
3. Read beyond a headline to definitions, code and version/unit provenance. Retain unresolved discrepancies rather than normalizing them away.
4. Make history, role format, input length and supplied information explicit experimental factors before attributing failure to body size or memory alone.

These are observer/research habits, not new rules imposed on the garden. They are concrete refinements to our verification and source reading, not evidence that any model behavior has improved.
