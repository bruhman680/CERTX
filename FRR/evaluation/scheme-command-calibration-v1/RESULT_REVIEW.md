## What worked, and what did not

Normal supplied-copy success consists entirely of exactly `(run (+ 2 3))`: one short-card and two broad-card replies computed 5. Normal literal, definition and page copying all failed. The broad-card copy total is 2/8 versus short 1/8, but two seeds and a few repeated targets do not establish a stable card benefit. It would be especially misleading to claim that the shortest command is always easiest: `(run 3)` failed in all four normal copy cells while the longer addition succeeded three times.

The four short variation replies retained example operands `1 1`: two emitted the complete example and computed 2; two omitted outer parentheses and failed validation. All eight variation goals failed, including broad-card replies containing example text plus malformed wrappers or prose. These results separate syntactic execution from following the requested arithmetic target. They do not show that the host computed the wrong sum: accepted commands computed the expression actually emitted.

Both feedback arms preserved this outcome pattern: two accepted wrong-example commands and two invalid replies per arm, with zero requested successes and no acceptance/task-success discordance between paired arms. Receipt feedback included actual status/error/value; in the accepted wrong-example cases it correctly said COMPUTED with value 2. It did not supply a task-aware message such as “that computes the example rather than the requested operands,” a correct command, or a suggested repair. Consequently this demonstrates no observed improvement from this receipt presentation over the practice cue; it does not test every form of corrective feedback or establish inability to learn from feedback. The shared example and prior reply remain visible in both continuation prompts.

## Adaptive example probe

The follow-up was chosen after observing example repetition and must be labeled adaptive/exploratory. It adds eight calls; the original four short variation replies are reused comparison records, not new generations.

With the example changed to `(run (+ 8 9))` and requested goals unchanged, all four new replies followed operands `8 9`: two complete commands computed 17 and two omitted outer parentheses. The changed-example prompts match the original example prompts in token length. With the example removed, all four replies were invalid; neither probe condition achieved a requested goal.

The operand switch is direct local evidence that example content influenced the emitted expression in these matched tasks/seeds. It strengthens the interpretation of example repetition beyond merely noticing repeated `1 1`. It does not identify an internal copying mechanism, prove that examples always override tasks, or provide a held-out estimate after adaptive selection. The no-example comparison also changes prompt length and available syntax support, so its failures cannot isolate a pure example effect.

## Adapter reference and limits

On the matched literal/definition copy subset, scale zero achieved 3/8 versus normal 0/8. All three reference successes were broad-card exact copies: one literal and two definitions. The published definitions passed the separate `double(3) == 6` host witness. These are supplied-definition copying and execution witnesses, not autonomous construction. Reference plain copying instead failed 0/4 against normal 3/4: the measured direction depends on task. Reference addition, page, variation and feedback were not tested, so no reference advantage on those tasks can be inferred.

The protocol audit's page scorer permissiveness did not affect these outcomes because no page action was accepted. The main helper pre-pinning gap remains a provenance limitation even though the adaptive plan pins those helpers later. Successful local commands justify a narrow next diagnostic about task/example binding; they do not establish constructive free play, a general model ranking, or a reason to begin a longer autonomous season.
