## Why use context forks

The preceding live detached contact changed a fictional filename from world_snapshot to runtime_feedback after a receipt arrived, but its entire conversation also grew. We could not identify which context component mattered. These tests preserve the exact saved input and change only declared field names or prior wording. They give pointwise input-dependence evidence without injecting corrections, solutions or tasks into the inhabitant's world.

Sources are the original compact-FRR branch's actual reply1/reply2 records from role-coupling-three-cycle-v1/cycle3. Their initial system mechanics plus compact FRR remain unchanged. ## What this contributes

High confidence: these exact input substitutions change this fixed body's generated artifacts; equal token counts rule out a total-length-only account of these particular contrasts. Controls reproduce archived outputs, and literal named-object patterns match the table.

The useful interpretation is narrower than a cognitive mechanism: transport/data labels can become nouns in unsupported object descriptions, while context history modifies the continuation. The source snapshots have no world_snapshot, directory_state, runtime_feedback or cell_results file; the observation lists entries and the receipt is null. A fluent notebook assertion can therefore reflect prompt content without documenting a read or a world event. This is a concrete reason to preserve the distinction between a label, a generated claim and acquired evidence.

The external CLAIM_LEDGER.md implements that reporting distinction with literal quotes, actual supplied types/values and scoped evidence checks. It is not model-facing guidance, a semantic success gate or a limitation on the inhabitant's permitted errors. String extraction remains descriptive, not an automatic semantic judge.

These diagnostics do not establish operational FRR benefit or harm: compact FRR was constant, not a treatment here. They do not test spontaneous action choice or repair, because no live-world execution was enabled. Zero world actions and zero notebook appends are **by design**, not failures by the model. No inference about durable learning, model internal belief, consciousness or an ability ceiling follows.

## Next strongest

The nearest generalization test is a small predeclared held-out set of receipt aliases with the same payload, roles and history, plus source controls. Choose names before outputs, report their tokenization/associations, preserve all outcomes and do not tune labels until one looks productive. This would test the reach of the current local dependency, not a universal language law.
