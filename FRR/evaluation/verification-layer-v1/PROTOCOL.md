# VL-C1: verification-layer prototype instrument contact

Prepared before this contact's execution, following PID-C1 and ES-C1. Question: can an executable contract layer distinguish supported, contradicted and unresolved scoped claims, preserve evidence/version bindings, and extend an adapter without silently rewriting prior verdicts? This is instrument validation on authored development cases. It is not a model-reasoning experiment or a general truth detector test.

Fixed budget: 22 authored fixtures, two versioned rule configurations, 44 evaluations, finite comparison/ledger checks; CPU only, no provider calls, no participant agents. Do not execute the broader research queue under this protocol. Record failures; repair through a disclosed amendment rather than overwriting a completed contact. Do not claim fixtures are independent or held out from implementation.

Ruleset 0.1 supports literal exact-rational equality. Ruleset 0.2 additionally supports true-state interval assessment conditional on supplied additive sensor-bias bounds. Both are prepared now, not historical deployments. The comparison is an adapter extension replay, not learned evolution or a historical improvement claim. Per-version expected keys are separately stored from contracts and not passed to evaluate(). Input scope and calibration assumptions are supplied, not inferred/authenticated. Unsupported semantics must remain unresolved.

22 cases include correct/incorrect arithmetic, exact fractions, missing/changed bytes, scope expansion, unavailable semantics, unimplemented criterion, undefined/forbidden expression, missing expression, malformed expected value, unsupported floating semantics, path escape, and eight sensor cases covering sufficient/insufficient/inconsistent bias bounds, interval ambiguity, inclusive tolerance boundaries and invalid input.

Prospective expectations: all per-version dispositions match authored keys; earlier literal-adapter dispositions remain identical; the interval extension resolves supported/contradicted cases while retaining uncertainty when bounds do not suffice. Integrity-only and unresolved-only comparators expose respectively unwarranted support and needless withholding; these intentionally weak baselines are not ordinary human/agent review or provenance-only reasoning competitors. Report each error type separately rather than select on a single favorable aggregate.

Ledger checks: append a versioned revision with an explicit prior event and note; verify old prefix preservation, rejection of an unknown revision parent and detection of changed payload without corresponding hash repair. Also test the limitation: a privileged writer can recompute the whole chain and pass the local hash check. This log is neither signed nor tamper-proof; independently anchored history is required for stronger integrity. One process writer lock does not guarantee semantic validity or source authenticity.

Freeze code, fixtures, keys, protocol and their manifest before the run. Preserve receipts, summaries, development ledger, stdout/stderr and source hashes. Domain-check pass is conditional scoped support; failed integrity/scope or missing information yields unresolved, not a claim of factual falsity. Adapter disagreement/unknown or higher verification effort does not itself establish truth. Core FRR prompts/schema remain unchanged. Behavioral efficacy and independent confirmation remain later work.
