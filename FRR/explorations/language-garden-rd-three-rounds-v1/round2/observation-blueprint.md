## Contract and boundary

Keep two linked observer records. The **event ledger** preserves what happened: exact input/rendering, generated token IDs and decoded text, author/source, order, available history, runtime policy and termination cause. The **interpretation ledger** points to quoted spans and records provisional frame, question, evidence and unresolved alternatives. Neither is sent back as a response template, success score or semantic approval gate.

A byte/order audit establishes record integrity. It does not establish truth, attention or understanding. Retain a revision beside its precursor; a later contradiction or correction cannot erase either. Fiction, imagined events and counterfactuals are not retroactively errors. If a later utterance asserts that earlier text contained particular words, that new record claim is checkable separately.

The continuing candidate uses the explicit native system framing and exact seed, one-call manual baseline, and optionally at most four calls total. Calls after the first use exactly “Another turn is available.” The ledger attributes these opportunities to the host. Record each human checkpoint decision and any reason or quoted span triggering suspension. This exposes contingent observer influence rather than calling scheduling neutral. EOS-only/empty decoded output, token cap, fault or context-bound breach pause without retry; nonempty EOS permits a checkpoint, not proof of willingness. No STOP convention is required.

Preserve every decoded contribution in subsequent native message history; archive original raw IDs separately. Re-rendered decoded history is not exact token replay. Save each complete rendered input and token count. The proposed bound is input ≤7936 plus output allowance 256 within declared 8192. Pause before overflow; no summary or hidden omission.

## A usable ledger example

The following is an illustration, not an observed run. IDs are external bookkeeping.

| Event | Saved evidence | Observer interpretation/action |
|---|---|---|
| E01 host call | System/seed bytes, native rendering, raw input IDs, policy, history selection | Initial opportunity; no independent outcome supplied |
| E02 resident reply | Raw output IDs; decoded “The moon ate the key”; EOS cause | Narrative contribution or metaphor; unresolved, no truth score |
| E03 checkpoint | Host decision, time, reason; exact continuation cue | Host-added opportunity; absence of refusal does not prove preference |
| E04 resident reply | “Earlier I wrote that the moon ate the key” plus source span | Checkable inscription claim; matching E02 supports this recall only |
| E05 optional offer | Separate encounter text, fixed rule/state, acceptance boundary | Offered; no encounter unless engagement is clear |
| E06 expectation | Exact pre-outcome span and information available | Interpretable prediction, ambiguous response, decline, or no prediction |
| E07 external receipt | Prior state, operation, independently computed resulting state, reveal time | Resolve eligible expectation; retain failures, do not send a score |

Wall-clock time orders host interactions; it is not resident experienced time. Include all opportunities and pauses, not only quotable successes.

## One optional contact, outside the initial expression window

If later authorized, offer a tiny symbolic encounter: a visible three-symbol sequence and a disclosed operation moving its first symbol to the end. Invite an expectation in ordinary language before the host applies that operation once. No resident command grammar or explanation requirement. If engagement is ambiguous, leave participation unresolved instead of extracting consent from unrelated prose.

Freeze initial state, operation, horizon and answer interpretation before reveal; derive the result externally from the frozen state and rule. Preserve the actual receipt even when it contradicts the expectation. The falsifiable question is simply whether an interpretable pre-reveal expectation matches that result; a subsequent prediction on a fresh sequence may show receipt use. This cannot establish transfer, learning or autonomy. Direct instruction-following is the strong simple rival. The receipt is world evidence; there is no additional correctness reward or automatic rubric feedback.

Report offered, engaged, declined, ambiguous, interpretable and independently resolved counts separately. Interface failures are observations about access. Before any side graph encounter, check whether the receiver's evidence plus a possible message can distinguish the target. Independent permutations of a symmetric graph can leave targets equivalent under every available relation. Use distinguishable equivalence classes or mark the instance unidentifiable; never score impossibility or missing interface competence as absent symbolic ability. Shared agent agreement is interpretation review, not replication.
