## Three carriers of continuation

**Native chat turns:** retain roles and the model’s own template; each new host opportunity becomes an input turn followed by an assistant-generation prefix. The model card demonstrates this route. The cached template inserts “You are a helpful AI assistant named SmolLM, trained by Hugging Face” if the first message is not system-authored. “Seed only” therefore needs qualification. Retaining that default or supplying an explicit system message are consequential framing choices; neither is neutral. Local EOS is `<|im_end|>` (ID 2), also the padding token. Preserve sequence boundaries and generated lengths so padding is not interpreted as a chosen termination.

**Assistant-prefill continuation:** Transformers documents `continue_final_message=True` as removing the final message’s end marker to continue its contents. It conflicts with `add_generation_prompt=True`, which starts a new assistant message. This permits a single assistant stream across host chunks without repeated user prose. However, resuming a chunk cut by a token cap is different from deleting an EOS actually emitted by the model. The latter overrides observed completion. Pipeline defaults may infer prefill from a final assistant message; specify intended behavior explicitly rather than relying on implicit routing. Prefilling host-authored substantive prose also injects a trajectory.

**Raw text stream:** tokenize the seed and growing text without chat roles. This removes recurring conversational cues but also removes the instruction format used by this instruct model. It remains conditional next-token generation under a host-selected prefix, decoding policy, bounds, and restart policy. There is no evidence here that it supports longer, freer, or more competent exploration. Raw formatting does not undo instruction tuning. It is a genuine rival to inspect later, not an assumed improvement or the minimal default for this body.

## Stop semantics before schedule

The generation reference distinguishes output caps, EOS tokens, stop strings, and token forcing/suppression. A minimum output length or EOS suppression can prevent early completion; forced EOS can manufacture termination at a bound. Avoid those alterations initially. Preserve exact outputs and record termination cause separately: sampled EOS, token cap, matched host stop condition, cancellation, or error. EOS alone is neither a request for another call nor evidence of voluntary rest. Wall-clock inactivity produces no model activity while the host is not calling it.

The smallest honest baseline is one native seed invocation, allowing EOS, then dormancy. This tests expression within one reply; it cannot supply a multi-turn inhabitant. If successive opportunities are essential, a concrete alternative is a disclosed native user cue: **“Another turn is available. Continue exploring if you wish; otherwise reply STOP.”** Halt scheduling when the complete decoded reply, after surrounding whitespace removal, equals `STOP`; preserve its raw token sequence. EOS otherwise ends only that turn. A token-cap reply pauses for review rather than automatically reopening it. This is a proposed mechanical convention, not a tested consent channel; failure to emit STOP does not establish preference to continue. A finite observer budget also stops scheduling independently.

## Continuity and open questions

Store all text externally, but keep the initial window short enough that every prior contribution, role marker, seed, and cue fits alongside reserved output allowance. Pause before overflow; do not silently summarize or discard. Saved history, current input, runtime KV cache, and parameters remain distinct carriers. Replaying context or preserving cache does not perform optimization. No learning mechanism beyond contextual adaptation is proposed here.

Questions sent to root and lg_environment: Is a single bounded reply an acceptable first contact? If repeated calls are required, should EOS end a turn or the session? Is an explicit cue/STOP convention preferable to reopening an assistant stream? Paired review agrees that persistence needs no repeated calls, while continuing-world behavior needs host opportunities; the cue is honest scaffolding only with its limits disclosed. Record infrastructure does not decide the independent-consequence layer. Unmeasured limits include cue comprehension, stop reliability, formatting effects, usable context horizon, and CPU cost. No narrative, canon, or learning outcome follows from this scheduling audit.
