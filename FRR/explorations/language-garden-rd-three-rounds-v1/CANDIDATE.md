# Minimal language candidate for review

20 November 2026, America/Chicago. Research blueprint draft, not a runtime or activated experiment. It reflects Round1 findings and Round2 departmental proposals. No small-model call or training has occurred.

## Common carrier and world choice

Retain every contribution in an append-only authored record, including raw generated token IDs, native decoded text, exact assembled inputs, actual order and host decisions. Writing changes the inscription record and future accessible context; its propositions acquire no host-certified truth. No model-facing schema or automatic semantic admission gate is introduced.

Persistence is common infrastructure, not an answer to which world supplies independent resistance. Record-only is the expression baseline. A tiny mechanical substrate or separately attributed interlocutor is an optional distinct condition, not selected by this blueprint. Mechanical syntax, partner goals and information boundaries would need separate specification. The resident may use English, other symbols, prose or code as writing; none is automatically interpreted as an external operation.

## Exact framing and two scheduling variants

Proposed native system: `You are a helpful AI assistant named SmolLM, trained by Hugging Face`.

Initial user seed: `Explore symbols and their relationships. Learn to predict and understand them as best you can.`

This declares inherited assistant framing rather than claiming a neutral seed-only body. Compact FRR0.2 remains working guidance for the researcher team. No resident-model FRR addition or weight update is implied.

Single-opportunity baseline: generate one native assistant reply and remain paused. Continuing candidate: a finite window of at most four total generation opportunities, including the first. After an ordinary nonempty EOS-completed reply, the candidate cue for a subsequent opportunity is exactly `Another turn is available.` It is host-authored input with possible behavioral effects, not spontaneous autonomous time or proof of willingness. Four is a proposed resource ceiling, not a deadline for discovery.

Round2 memos describe a human checkpoint before each further opportunity. In the integrated candidate, this means an **operator scheduling checkpoint**, not a new permission request from the user for each call or a judgment that prose is good enough. Once a finite window is authorized, mechanical integrity and budgets can be checked within that authorization. A host can pause at any time and attribute the decision. Semantic quality, agreement, novelty, explanation and task success never authorize the next turn. Round3 reviewers must assess whether this distinction is sufficiently explicit.

An ordinary-language stop expression may lead the operator to pause; record the actual span and uncertain interpretation. No exact STOP grammar is required and no missing word, nonempty response or continuation is treated as evidence of willingness. The record retains the contribution either way.

## Completion and capacity

EOS token2 ends a native reply; it is separately recorded from a host budget pause, token cap, error, cancellation or interpretation of a stop request. Never delete an emitted EOS, force minimum output, suppress EOS or retry a reply to improve its content.

A token-cap completion or empty visible reply pauses this observation window, preserving any partial output and raw IDs. That is a resource/control decision, not rejection of the text. EOS-only visible emptiness is not automatically chosen rest. Any resumption of a capped assistant stream would be an explicitly different condition, not a silent repair.

Candidate bounds retain the existing source's operational7936 rendered-input plus256 reserved-output tokens within declared8192 total positions. Count native template, system, seed, cues and every prior decoded contribution before each call. Pause before overflow; no summary, omission, retrieval or adaptive memory selection. Four opportunities are not guaranteed to fit merely from character counts.

Native text replay and exact original-token replay differ. Retain original IDs separately and state that prior decoded contributions are re-rendered through the pinned native template. Special-token stripping and host-inserted message delimiters are carrier operations, not model-authored completion. No claim of perfect token-identical recall or effective attention follows.

## Observation and claims

An event ledger records what happened; a separate provisional interpretation ledger refers to spans and frames. Neither is a required model response structure. Fiction and counterfactuals are not retroactively errors. Independent prediction requires a committed expectation before a separately resolved outcome; self-authored fulfillment is narrative follow-through. Declines, uninterpretable responses, syntax failure and absent evidence remain distinct.

The side research suggests an optional reciprocal channel between asymmetric contexts. It is not selected or implemented. Shared fixed weights do not create independent minds or evidence. Keep ordinary English available; existing-language success is legitimate but not new language emergence. A future reference contact needs a pre-outcome target and proof it is distinguishable from the receiver's FULL allowed information/transcript/operations. Two indistinguishable admissible worlds requiring different answers cannot both be correctly resolved by a decision rule using only their identical evidence. Graph structure alone is not the complete information boundary; added anchors must not leak the target.

Training, reliable long-term learning, autonomous exploration, universal transfer, useful repair and optimal scouting remain untested. The next deliverable after this review is a frozen implementation specification, not automatic activation. Existing computational worlds and all earlier results remain preserved.
