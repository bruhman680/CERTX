# Reviewed language blueprint proposal

20 November 2026, America/Chicago. Reviewed proposal after three sequential research rounds, not an activation-ready runtime or experiment. This revises the frozen Round2 CANDIDATE.md; it does not overwrite that record. No small-model call or training has occurred.

## Common carrier and world choice

Retain every successfully returned or otherwise recoverable contribution in an append-only authored record, including available raw generated token IDs, native decoded text, exact assembled inputs, actual order and host decisions. Mark unavailable traces explicitly; never manufacture an empty resident message for missing output. Writing changes the inscription record and future accessible context; its propositions acquire no host-certified truth. No model-facing schema or automatic semantic admission gate is introduced.

Persistence is common infrastructure, not an answer to which world supplies independent resistance. Record-only is the expression baseline. A tiny mechanical substrate or separately attributed interlocutor is an optional distinct condition, not selected by this blueprint. Mechanical syntax, partner goals and information boundaries would need separate specification. The resident may use English, other symbols, prose or code as writing; none is automatically interpreted as an external operation.

## Exact framing and two scheduling variants

Proposed native system: `You are a helpful AI assistant named SmolLM, trained by Hugging Face`.

Initial user seed: `Explore symbols and their relationships. Learn to predict and understand them as best you can.`

This declares inherited assistant framing rather than claiming a neutral seed-only body. Compact FRR0.2 remains working guidance for the researcher team. No resident-model FRR addition or weight update is implied.

Single-opportunity baseline: generate one native assistant reply and remain paused. Continuing candidate: a finite window of at most four total generation opportunities, including the first. After an ordinary nonempty EOS-completed reply, the candidate cue for a subsequent opportunity is exactly `Another turn is available.` It is host-authored input with possible behavioral effects, not spontaneous autonomous time or proof of willingness. Four is a proposed resource ceiling, not a deadline for discovery.

Round2 memos describe a human checkpoint before each further opportunity. In the integrated candidate, this means an **operator scheduling checkpoint**, not a new permission request from the user for each call or a judgment that prose is good enough. Once a finite window is authorized, mechanical integrity and budgets can be checked within that authorization. A host can pause at any time and attribute the decision. Semantic quality, agreement, novelty, explanation and task success never authorize the next turn. Round3 reviewers accepted this distinction as a proposal; it remains an implementation requirement.

All committed contributions enter the record before interpretation. A provisional reading of a possible resident-addressed stop request may affect scheduling, never admission. Quoted, fictional, hypothetical and third-person stop language are different frames. If uncertainty motivates a pause, record an operator precaution with the actual span, not confirmed model preference. No exact STOP grammar is required and no missing word, nonempty response or continuation is evidence of willingness.

## Completion and capacity

EOS token2 ends a native reply; it is separately recorded from a host budget pause, token cap, error, cancellation or interpretation of a stop request. Never delete an emitted EOS, force minimum output, suppress EOS or retry a reply to improve its content.

A normally returned token-cap reply or literally empty decoded string (zero Unicode characters) pauses this observation window, retaining the returned partial text and IDs. Whitespace-only text remains a nonempty contribution; preserve it without normalization or an inference of willingness. That is a resource/control decision, not rejection of the text. EOS-only visible emptiness is not automatically chosen rest. Archive emitted EOS in raw IDs; native decoded-history replay removes special tokens and the host template supplies delimiters, which is not literal original-token replay. Any resumption of a capped assistant stream would be an explicitly different condition, not a silent repair.

The inherited body accumulates output IDs in memory and returns them only after generation and a final resource guard. Cancellation or exception can leave locally generated tokens unavailable. Before activation choose one recording policy: (A) preserve every returned/recoverable artifact, record a started-but-unresolved call and unknown partial trace, pause without replay; or (B) implement and separately test a durable token journal before claiming complete interrupted-token capture. Neither policy is selected or implemented by these documents. Unavailable output, verified zero tokens, EOS-only visible emptiness and a whitespace contribution remain distinct.

Candidate bounds retain the existing source's operational7936 rendered-input plus256 reserved-output tokens within declared8192 total positions. Count native template, system, seed, cues and every prior decoded contribution before each call. Pause before overflow; no summary, omission, retrieval or adaptive memory selection. Four opportunities are not guaranteed to fit merely from character counts.

Native text replay and exact original-token replay differ. Retain original IDs separately and state that prior decoded contributions are re-rendered through the pinned native template. Special-token stripping and host-inserted message delimiters are carrier operations, not model-authored completion. No claim of perfect token-identical recall or effective attention follows.

## Observation and claims

An event ledger records what happened; a separate provisional interpretation ledger refers to spans and frames. Neither is a required model response structure. Fiction and counterfactuals are not retroactively errors. Independent prediction requires a committed expectation before a separately resolved outcome; self-authored fulfillment is narrative follow-through. Declines, uninterpretable responses, syntax failure and absent evidence remain distinct.

The side research suggests an optional reciprocal channel between asymmetric contexts. It is not selected or implemented. Shared fixed weights do not create independent minds or evidence. Keep ordinary English available; existing-language success is legitimate but not new language emergence. A future reference contact needs a pre-outcome target and a predeclared eligibility argument that SOME permitted informative message or interaction can distinguish it given fixed nonmessage evidence. The receiver need not already know the target before communication. Then separately assess whether the ACTUAL transcript identifies it. The information boundary covers the FULL allowed evidence/transcript/operations. Two indistinguishable admissible worlds requiring different answers cannot both be correctly resolved by a decision rule using only their identical evidence. Graph structure alone is not the complete information boundary; added anchors must not leak the target.

Training, reliable long-term learning, autonomous exploration, universal transfer, useful repair and optimal scouting remain untested. Before activation freeze the selected scheduling variant, exact model/checkpoint/decoder/runtime/renderer pins, stop/empty/interruption handling, budgets and input assembly. Optional-contact participation and interpretation rules belong in a separate predeclared observer protocol and never gate prose admission. The next deliverable is this frozen implementation specification plus resolution of interrupted-output recording, not automatic activation. Existing computational worlds and all earlier results remain preserved.
